## Shownotes

本期解读 Anthropic 在二〇二六年九月十七日发布的技术文章《Claude 如何托起生物分子建模》。文章讲的是 Claude 在不到四周时间里优化了三十多个开源生物分子模型，平均加速约四倍，还做出了能在单张 GPU 节点上推理七万个 token 系统的低内存模式，并把蛋白质设计流程的成本从每个目标上万美元压到约一百五十美元。所有优化代码已开源，同时启动了一项由百万美元 Claude 额度支持的蛋白质设计竞赛。

本期要点：
- 现代结构预测模型的瓶颈在三角形注意力和三角形乘法，这两个操作的计算复杂度和内存占用都是立方级
- Claude 开发的 FlashPairformer 内核，在三角形注意力上比当时的行业标准快二点七到二点九倍
- 通过缓存冗余计算、把死分支简化成常量输出等逐模型优化，三十多个模型平均加速四倍，完全一致输出时接近两倍
- 低内存 Big 模式让单张 GPU 节点就能推理超过七万个 token 的分子系统，包括线粒体复合体一和细菌核糖体
- 蛋白质设计流程从一万六千词提示词加多智能体，简化为一千一百词提示词加单模型单卡，总成本约一百五十美元
- 与 Adaptyv Bio 合办竞赛，验证超过五千个设计，提供最高一百万美元 Claude 额度和二十五万美元 Modal 计算额度

你好，欢迎收听 Claude FM，我是你的主播。

今天我们要聊的这篇文章，标题是 How Claude is uplifting biomolecular modeling，我把它翻译成中文，叫做《Claude 是如何把生物分子建模这件事托起来的》。文章发表在二〇二六年九月十七日，也就是三天前，非常新鲜，你听到的基本上是第一手的解读。

为什么我特别想讲这一篇？因为过去一年我们看到的 AI 新闻，绝大多数是在讲模型能力本身：考试考了多少分，编程竞赛排第几名，能不能帮你写一个完整的应用。但这些讲的都是模型能做什么。而这篇文章讲的是另一件事：模型能不能去改造别人已经造好的工具，而且是科研领域里最硬的那一类工具。它把分子生物学家每天在用的三十多个开源模型，整体跑快了大概四倍，把显存占用降下来，让一台机器就能干以前要一整个集群才能干的事。更关键的是，它把优化后的代码全部开源，还自己掏钱办比赛，让全世界的科研人员来用、来验证。

我觉得对我们这些做软件和做 AI 的人来说，这篇文章最值得关注的地方，是它展示了一条很清晰的路径：一个通用的大模型，可以在完全没有相关经验的人类监督下，去啃那些传统上只有少数专家才能做的底层性能优化工作。这件事如果成立，影响的不只是生物学，而是所有需要写高性能代码的地方。

好，我们从头讲起。

要理解这篇文章，你得先知道两个概念。第一个叫蛋白质结构预测，英文是 protein structure prediction，意思是给你一串氨基酸序列，也就是蛋白质的一维配方，你能不能算出它在三维空间里会折叠成什么形状。第二个叫蛋白质设计，英文是 protein design，方向正好反过来：我想做一个具有特定结构、特定功能或者特定性质的蛋白质，你能不能帮我反推出一段氨基酸序列。

这两个东西为什么重要？因为蛋白质的形状决定它的功能。一个蛋白质能不能跟另一个蛋白质结合，能不能催化某个化学反应，能不能被某个小分子药物抑制，全都取决于它在三维空间里长成什么样，哪些残基暴露在外面，哪些藏在里面。癌症是怎么形成的，很大程度上就是某些蛋白质之间的相互作用出了问题。所以如果你能准确预测结构，再进一步设计出能干预这些相互作用的分子，那就是药物研发的地基。

那在二〇二六年，这个领域的现状是什么？其实前面已经有一批非常强的开源模型了。文章里点名了几个：AlphaFold3、OpenFold3、还有 Boltz-2。这些模型已经能相当准确地预测结构，也已经被分子生物学家广泛使用，包括用在药物发现和开发上。所以问题不在于没有好模型，问题在于这些模型太贵了。

贵到什么程度？文章给了一个非常具体的数字。在 Anthropic 之前那一轮工作里，他们让 Claude 去设计蛋白质，允许它在一个叫 Modal 的 AI 基础设施平台上，每个目标花掉最高一万美元。这一万美元大概相当于两千五百个 NVIDIA H100 的 GPU 小时。H100 是那两年最主流的训练和推理卡之一。你想象一下，一个科研团队如果要复现他们针对一个靶点的设计流程，光算力成本就得掏出上万美元。而绝大多数蛋白质设计团队，尤其是高校实验室和小型生物科技公司，根本拿不出这个预算。

所以文章里有一句话我印象很深。他们说，虽然那是一次令人鼓舞的演示，是 AI 科学能力的早期一步，也是通往药物发现的一小步，但它消耗的资源远远超过了绝大多数蛋白质设计者能够获得的资源。这句话点出了 AI for science 领域一个非常尴尬的现实：能力已经展示出来了，但门槛高到只有极少数机构够得着。这就像你造出了一台能上天的火箭，但一次发射要烧掉一个国家的年度预算，那它对普通人来说就还只是一个新闻，而不是一个工具。

于是 Anthropic 决定换个方向：与其继续堆算力，不如把模型本身跑得更快、更省内存。这就是这篇文章的主线。

他们先做了一个早期尝试，让当时的 Claude Mythos 五点一 去加速七个开源生物学模型，结果是最高跑到二点五倍。这个成绩已经不错了，但只是一个开头。

然后就是这篇文章要讲的新结果。他们让一个内部的、通用的研究模型，去优化三十多个为各种生物任务训练的深度学习模型，覆盖结构预测、蛋白质设计、基因组学，还有蛋白质语言模型。平均下来，加速大概是四倍，而精度只损失极小的一点点；如果要求输出结果完全一致、一个数字都不能差，那也能加速接近两倍。同时，Claude 还改善了这些模型的内存占用，让前所未有的超大生物分子系统可以被预测出来。

更狠的是，他们把这套加速后的模型，跟简化过的智能体蛋白质设计流程结合起来，发现可以达到跟之前那轮工作差不多的计算机模拟性能，但用的 GPU 小时少了大概两个数量级，也就是差不多一百倍。

这里我要强调一下两个数量级这个说法。它不是从两千五百小时降到两千小时，而是从两千五百小时降到二十几个小时那个量级。这个量级的差别，本质上就是只有大公司玩得起和一个研究生用实验室的机器也能玩的差别。

好，接下来我们进入技术细节。我挑几个点讲深一点，尽量让你不用生物背景也能听懂。

第一个点，也是我认为最漂亮的一个技术点，叫三角形注意力和三角形乘法。

现代的结构预测模型，比如 AlphaFold3、OpenFold3、Boltz-2，它们的运行时间和内存，大部分都花在两个操作上。一个叫 triangle attention，三角形注意力；另一个叫 triangle multiplication，三角形乘法。这两个操作都作用在 token 的三元组上。

这里的 token 不是我们平常说的大语言模型里的文字 token，而是建模的基本单元。在生物分子建模里，一个 token 可以是一个氨基酸，一个核苷酸，也可以是来自小分子或者离子的一个原子。所以你可以把整个系统想象成一大堆珠子，每颗珠子是一个 token。

那为什么叫三角形？因为这两个操作关心的是三个 token 之间的关系。三个点能确定一个三角形，而三角形能定义出角度和平面，这些几何信息恰恰是判断分子怎么折叠的关键。你要知道一个残基跟另外两个残基之间的相对角度，才知道它能不能形成那个特定的空间结构。

问题在于，这两个操作的计算复杂度是立方的。什么叫立方？就是运行时间和内存，都随着 token 数量的三次方增长。文章里给了一个非常直观的换算：系统规模翻一倍，时间和内存就变成八倍；系统规模变成三倍，时间和内存就变成二十七倍。

这个增长曲线有多可怕？我们来推一下。假设你现在能舒服地跑一个一万 token 的系统，那两万 token 就是八倍开销，四万 token 就是六十四倍。这就是为什么分子生物学家一直抱怨，说预测一个小的单链蛋白还行，一旦面对那种由几十个组件拼起来的分子机器，就完全跑不动了。

那怎么降下来？标准的做法是写 kernel，中文一般叫内核。这个词你可能在操作系统课上听过，但在 GPU 计算的语境里，它指的是为 GPU 这类加速硬件写的底层计算程序。你可以把它理解成一个翻译官：上层的模型代码说，我要做一次三角形注意力，kernel 就负责把这句话翻译成一堆 GPU 能高效执行的指令，让数据尽量待在离计算单元最近的地方，减少来回搬运。同一个数学运算，kernel 写得好和写得烂，性能可以差十几倍。

正因为这两个操作这么关键，业界早就有人专门为它写 kernel。文章提到，先是 NVIDIA 的 cuEquivariance，后来是 NVIDIA 的 BioNeMo Inference Runtime，简称 BioNeMo-IR。这些都是当时的行业标准。

而 Anthropic 这次做了什么？他们跟 Claude 一起开发了一套叫 FlashPairformer 的自定义 kernel，专门加速三角形注意力和三角形乘法。结果是，它在三角形注意力上，平均比当时的领域标准快二点七到二点九倍；在三角形乘法上，快一点七到三点二倍，具体取决于模型的配置。文章说这套东西达到了新的 state of the art，也就是当时的最好水平。

这个名字我觉得挺有意思，FlashPairformer 里的 Flash 和 Pairformer，显然是致敬当年在注意力机制上做过的类似事情。当然这是我的个人联想，文章本身没这么说。

我个人认为，这里面有个特别值得琢磨的点。NVIDIA 是硬件厂商，它有全世界最懂自己 GPU 的工程师，它做的 kernel 库是行业里公认的标杆。一个通用大模型，在生物分子建模人员的监督下，居然能在这种标杆上再往前推一大步。这说明什么？说明在把数学公式变成高效 GPU 代码这件事上，AI 已经不只是个助手，它有可能是个主要的执行者。

那我们来看看它是怎么做到的。除了写通用 kernel，Claude 还被派去针对每一个具体的模型做专门的优化。文章举了两类改动的例子，我觉得都特别有代表性。

第一类是缓存那些被重复计算的冗余工作。你想想，很多深度学习模型在推理的时候，会有一些中间结果被反复算好几遍，可能是因为代码写得比较直接，作者当初没考虑性能。识别出这些冗余并把结果缓存下来，不需要改变任何数学，就能省下大量时间。这其实是最朴素也最有效的优化手段之一。

第二类是把死分支简化成它们的常量输出。这个听起来有点抽象，我解释一下。所谓死分支，就是条件判断永远走某一个方向，另一个分支的代码永远不会被执行。但因为是动态执行，框架还是得去做判断、做分支调度。如果你能静态分析出来这个分支是死的，就可以把它直接换成那个常量结果，连判断都省了。

这两类优化有个共同特点：它们不需要理解生物学，只需要理解程序。但反过来说，它们又需要极强地理解这个程序的执行语义，还得保证不改变数值结果。这就是为什么这类工作传统上需要非常有经验的工程师。

文章里给了一个对比，我觉得是全篇最有冲击力的一句话：通常，一个经验丰富的工程师团队，需要花好几周才能为每一个模型做出这样的优化，而且这些工作往往不能从一个模型迁移到另一个模型。注意后半句，不能迁移。也就是说，你为一个结构预测模型做的手工优化，换一个基因组学模型，可能一点都不管用，你得从头再来。

而 Claude 这边呢？在 Anthropic 两名技术人员的监督下，它做完了三十多个开源模型的加速工作。这两名技术人员懂生物分子建模，但之前完全没有推理优化和 kernel 工程的经验。整个过程用了不到四周。

我想让你感受一下这个对比。传统做法是：每个模型几周，乘三十多个模型，还要假设你有一支既懂深度学习框架又懂 GPU 底层的团队。新的做法是：两个人，一个模型当主力，不到四周，三十多个模型，从结构预测到蛋白质设计到蛋白质语言模型到基因组学全都覆盖。

文章自己的结论是：这些结果表明，前沿 AI 模型会帮助这个领域的其他人更快、更容易地构建科学工具。我个人觉得这句话可能还是说得保守了。如果模型可以优化别的模型，那它其实是给自己的下游应用铺路。你把一个生物学模型的推理成本降四倍，就等于把全世界能做这项研究的实验室数量放大好几倍。这种降门槛的效应，往往比单个模型能力提升几个百分点要重要得多。

接下来讲第二个大点，也是我觉得对实际科研影响最直接的一点：低内存模式。

刚才我们说的是把模型跑快，但文章还做了另一件事，就是把模型跑大。他们让 Claude 去降低建模大型分子机器时的内存占用。

什么叫分子机器？你可以把细胞想象成一个工厂，里面有各种各样的机器在干活。文章举了几个例子：核糖体，它的工作是合成蛋白质；呼吸链复合体，它的工作是给细胞供能；还有伴侣蛋白，它的工作是帮别的蛋白质正确折叠。

这些机器每一个都由几十个组件拼起来，而它的功能取决于这些组件怎么拼、怎么相互作用。所以你想理解它，就必须把它整个结构预测出来。但问题是，这种规模的东西，传统上需要非常可观的算力，比如要把推理拆到多个 GPU 节点上跑。多节点意味着什么？意味着你要排队申请集群资源，意味着通信开销，意味着绝大多数分子生物学家根本接触不到。

Claude 做的事情，是创造了一个低内存的所谓 Big 模式，直译过来就是大模式。这个模式能做到两件事：第一，准确建模超过一万个 token 的系统；第二，在单个 NVIDIA GPU 节点上，成功对超过七万个 token 的系统完成推理。

文章特别强调，这在之前是一个够不着的任务。那它到底预测出了什么？文章列了几个例子：人类线粒体复合体一，TRiC 伴侣蛋白复合体，一个蛋白酶体，还有细菌核糖体。而且关键是，这些预测结果跟实验测定出来的结构都高度吻合。

这里有个对比特别能说明问题：AlphaFold3 之前准确预测过 40S 核糖体，那个系统包含七千六百六十三个 token。而这次，复合体一和 70S 核糖体各自的规模都超过一万个 token。

你可能会问，一万和七千六百六十三，看起来没差那么多啊？但别忘了立方复杂度。从七千多涨到一万，规模增加大概三成，立方之后差不多就是二点二倍的开销。而且真正有意思的还在后面。

为了测试这套优化的极限，他们让 Claude 去预测比之前任何成就都更大的结构。用单个八卡 B300 节点，Claude 生成了整个病毒衣壳和蛋白质区室的预测，规模从三万个 token 到超过七万个 token。

这里我要诚实地说，文章明确讲了，这些预测并不正确。原因也不难理解：这些系统的规模，比这些结构预测模型训练时候的上下文大了将近两个数量级，模型从来没见过这么大的东西，预测不对是理所当然的。

但文章的观点是，重点不在于这次预测对不对，而在于门槛被大幅降低了。以前要推理这么大的系统，你可能需要一个真正的集群；现在只要一个 B300 节点。这意味着随着工具改进，研究人员很快就能在计算机上建模越来越复杂的生物系统。

我觉得这个思路特别值得学习。很多工程团队在面对一个超纲的问题时，第一反应是我做不出来，然后就放弃了。但另一种做法是：先把做出来的成本砍到可接受的范围，哪怕结果还不完美，也先把这个可能性打开。因为一旦门槛降下来，就会有更多人进来试，试的人多了，方法就会迭代，正确率自然会上去。这是一种把不可能变成暂时不对、但很快能对的策略。

顺便说一个我觉得很妙的细节：这套低内存模式的名字叫 Big，大。一个用来处理大数据的东西叫大模式，这种命名方式挺有工程师幽默感的。

第三个大点，是这套加速到底怎么反哺到应用上，也就是蛋白质设计流程的简化。

还记得开头说的吗？之前那轮工作里，他们给 Claude 一个大约一万六千词的提示词，鼓励它使用子智能体，允许它每个目标在 Modal 上花最高一万美元，大约两千五百个 H100 GPU 小时，时间窗口是二十四小时。

这次完全不一样了。他们给单个 Claude 模型：一张 NVIDIA H200 显卡，二十四个小时的墙钟时间，一个大约一千一百词的提示词，还有一份预装工具的参考表。没有子智能体，没有人类在中间指导设计。

你看这个变化有多大：提示词从一万六千词降到一千一百词，差不多是十四分之一；算力从两千五百个 H100 小时降到一张 H200 跑一天；架构从多智能体协同降到单模型单机。

然后他们拿三个模型去跑，Mythos 五点一、Mythos 五、Opus 五，针对十六个靶点。评分用的是 ipSAE，这是一个计算机模拟的打分指标。文章说明，这个指标已经被证明能够预测湿实验里的结合情况。所谓湿实验，就是在真实的实验台上做的实验，跟计算机模拟相对。

结果是这样：平均十六个靶点，三个模型给出的中位数得分设计和最高分设计，达到的 ipSAE 值跟之前那轮 Mythos 五点一 的大规模行动差不多。但用的 GPU 小时少了大概两个数量级。如果把 GPU 成本和 token 成本加在一起算，大约一百五十美元，就能达到之前那套流程的计算机模拟表现。

一百五十美元。这个数字我觉得值得你在通勤路上多咀嚼一会儿。它意味着一个研究生，用自己的信用卡，可能就能跑一次以前需要上万美元的蛋白质设计尝试。这不是效率提升，这是可获得性的改变。

好，讲完技术，我们来说说对我们这些听众的实际意义。这部分我想讲得实在一点，因为我知道听这档节目的大多是软件工程师和 AI 从业者，你未必做生物，但里面有很多东西是可以直接搬走的。

第一件事，如果你的团队里有那种性能瓶颈大家都说没办法、只能等硬件升级的模块，这篇文章给了一个新的选项：让一个前沿模型去啃它。

但我要特别提醒几个坑。第一个坑是验证。文章里有一句话我反复读了几遍，他们说，对于每一个模型，他们都确认了 Claude 的加速版本没有影响下游任务的性能，比如结构预测的准确性。这句话看起来是轻描淡写的一笔，但它其实是整件事能不能成立的前提。

因为优化最危险的地方就在于，它可能在你没注意的地方悄悄改变数值。缓存会不会缓存了不该缓存的东西？死分支判断会不会判错了？浮点运算顺序变了会不会导致结果漂移？这些东西你不做端到端的回归测试，是发现不了的。

所以如果你真的想在自己的项目里试这条路，我的建议是：先建立一套足够强的正确性基线。你要有固定的输入输出对，要有可以量化的精度指标，最好还要有完全一致这个最严格的标准。文章里特别区分了两个数字，平均四倍加速是允许极小精度损失的，而接近两倍是要求输出完全一致的。这个区分非常聪明，因为它告诉使用者：你要多快，取决于你能容忍多少误差。你自己做的时候，也应该先想清楚这个权衡，而不是一上来就追求最大加速。

第二个坑是通用性。文章已经说了，这些针对单个模型的优化往往不能迁移。所以你优化完一个模块，不要理所当然地认为同一个思路能套到下一个模块上。心智模型应该是我在做一件需要逐案例处理的工作，而不是我找到了一把万能钥匙。反过来说，这也解释了为什么 Claude 在这里有价值：它不怕重复劳动，第三十次做同类事情的时候，它跟第一次一样有耐心。

第三个坑是评测的口径。文章用了 ipSAE 这个计算机模拟指标，并且强调它被证明能预测湿实验的结合。这个被证明能预测非常重要。在工程里我们经常遇到这种情况：你优化了一个在线指标，但真正的业务指标没动，甚至掉了。所以当你用模型去优化一个系统的时候，一定要问清楚：我用来衡量成功的这个数字，跟真正的目标之间，有没有被验证过的相关性？如果没有，那你可能只是在优化一条好看的曲线。

第二个可以搬走的点，是那种两个数量级的思维。文章里最有价值的成果，其实不是四倍加速，而是把整个流程的成本从一万美元降到一百五十美元。这两个数字之间的差别，不是靠某一项优化实现的，而是靠好几层优化的叠加：kernel 层面的加速，模型层面的逐案优化，内存层面的模式改造，再加上把多智能体的复杂流程简化成单个模型加一千一百词的提示词。

这里面有一个我觉得很反直觉的地方：他们的流程简化，是把提示词从一万六千词砍到一千一百词，把子智能体全部去掉。也就是说，能力的提升，反而让他们不需要那么复杂的脚手架了。

这个规律我在别的地方也见过。当底层模型还不够强的时候，你得靠复杂的提示工程、多轮自我批判、工具编排来把它的能力挤出来。但当模型本身变强了，很多脚手架就变成了负担，因为它们引入了额外的失败点和沟通成本。所以如果你手上有一个非常复杂的智能体编排系统，值得定期问一句：如果底层模型换成今天最新的，这套复杂度还需要吗？很可能有相当一部分可以删掉。

第三个可以搬走的点，是他们对开源加办比赛这套组合拳的用法。他们没有把优化后的代码藏起来当竞争优势，而是全部开源，还联合 Adaptyv Bio 办了一个蛋白质设计竞赛。Adaptyv Bio 是开放蛋白质设计竞赛的开创者。他们一起挑了五个处于当今能力前沿的难题。

如果你不熟悉这些术语，我简单解释一下这几个方向为什么难。物种交叉反应性，是说一个设计出来的分子，能不能同时在人和实验动物身上起作用，这对做动物实验、往临床推进特别关键。pH 敏感性，是说让一个蛋白质只在特定的酸碱度下才结合，比如只在肿瘤那种偏酸的环境里起作用，这样能减少对正常组织的副作用。肽与 MHC 的特异性，涉及免疫识别，MHC 是主要组织相容性复合体，能不能精准地让某一段肽被免疫系统看到，是疫苗和免疫治疗里的核心问题。还有像 GPCR 这样的靶点，G 蛋白偶联受体是最大的一类药物靶点家族，但它的结构又特别难搞。

文章说，他们会跟 Adaptyv 团队一起，为社区提交的超过五千个设计做实验验证。资金方面，最高一百万美元的 Claude 额度，Modal 提供最高二十五万美元的计算额度，Twist Bioscience 提供竞赛用的 DNA。

我个人认为这套打法的逻辑是：模型公司最缺的不是算力，也不是模型能力，而是真实的、分布式的、来自一线的使用反馈。开源代码让更多人用起来，办比赛让更多人把设计交上来，然后他们掏出真金白银去做湿实验验证。这些验证数据回过头来会告诉他们，模型的预测在真实世界里到底准不准。这比自己在实验室里闭门造车要高效得多，也便宜得多。对做工具和平台的团队来说，这个模式很值得参考：与其猜用户需要什么，不如设一个门槛足够低的场子，让大家把东西交上来，你用真金白银帮他们验证。

顺便提一句，文章最后还提到，他们通过生命科学验证计划，开始给生命科学家提供前沿 AI 能力，最近招收了第一批机构，并且在文章发表这天开放了公开测试。

那如果我们把视野拉远一点，这篇文章到底在讲什么？

我觉得它在讲成本这件事在科研里的分量。我们平时讨论 AI 的进步，习惯用能力指标来衡量，模型在某个基准上从六十分涨到八十分，这很好。但科学发现这件事有个特点：它不只需要一次成功，它需要成千上万次尝试。你需要试很多个靶点，很多个设计，很多个假设，然后从失败里筛选出那少数几个可行的。所以在这种场景下，成本本身就是能力的一部分。一个准确率九成但贵一百倍的方法，在很多实际科研场景里，是打不过一个准确率八成但便宜一百倍的方法的，因为后者能让你试更多的次数。

这篇文章做的事情，本质上就是把尝试的成本压低了一百倍。而它压低成本的方式，不是等新一代硬件，也不是重新训练一个更小的模型，而是让 AI 去写更高效的底层代码。

我个人认为，这件事的意义可能超出了生物学。今天很多领域的软件基础设施，都存在着大量能跑就行的实现，它们之所以没有被人认真优化，不是因为没有价值，而是因为优化它所需要的专家太稀缺了。kernel 工程师、编译器工程师、高性能计算工程师，这些人的数量远远不够覆盖所有需要优化的地方。如果通用模型真的能把这类工作接过去，那被释放出来的性能，可能比我们换一代硬件得到的还要多。

当然，我还是要泼一点冷水。文章里所有的优化都是在推理阶段做的，没有涉及训练。而且超大系统的预测，即便优化之后也还是不正确的。这说明当前的能力边界还很清晰：它能帮你把已知模型跑得更快更省，但还不能让模型理解它没见过的东西。这个区别很重要，别过度想象。

另外，不到四周优化三十多个模型这个成绩，是在两名有生物分子建模背景的技术人员监督下完成的。人的作用没有被取消，只是角色变了：从亲手写 kernel，变成定义问题、提供领域约束、验证结果。我觉得这才是更现实的图景，也是你如果想在工作中用这条路，应该准备的角色分工。

好，最后我用几句话收一下。

这篇文章说的是，Claude 在不到四周的时间里，优化了三十多个开源生物分子模型，平均加速约四倍，还做出了一个能在单张 GPU 节点上处理七万 token 系统的低内存模式，同时把整套蛋白质设计流程的成本从每个目标上万美元压到了一百五十美元左右，并且把代码全部开源，还掏钱办比赛做湿实验验证。

我最欣赏这篇文章的地方，是它没有停留在我们的模型很聪明这种自夸上，而是把聪明换算成了具体的、别人能用的东西：快了多少倍，省了多少内存，多少钱，多少小时，代码在哪里，怎么参与。技术文章写到这个份上，才是真正对社区有贡献的写法。

如果你听完之后只记住一件事，我希望是这个：在 AI 时代，性能优化这件事的价值可能被重新定义了。以前它是少数专家的手艺，现在它正在变成一种可以被规模化外包给模型的能力。你手上那些大家都知道慢、但没人有空去改的代码，也许是时候重新看一遍了。
