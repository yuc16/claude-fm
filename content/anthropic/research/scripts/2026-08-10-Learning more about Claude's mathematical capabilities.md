先把预期放稳一点。原文并不是说 Claude 证明了黎曼猜想，也不是说数学家可以退休了。Anthropic 自己也明确说，他们不预期 Claude 使用的技术会导向黎曼猜想本身的证明。真正有意思的是，AI 模型开始在非常专业、非常长链条、依赖几十年文献积累的数学研究里，做出一种“接力式”的贡献。它像一个极其勤奋、会读文献、会试错、会写代码、会调动很多小助手的研究员，虽然还需要人类专家把关，但已经不只是把已知定理复述一遍。

我们先把背景说清楚。黎曼猜想是数学里最著名的未解问题之一，最早可以追溯到一八五九年，和黎曼 zeta 函数有关。它之所以重要，是因为 zeta 函数和素数分布有深层关系。素数就是只能被一和自己整除的正整数，比如二、三、五、七、十一。我们小时候觉得素数像是散落在数轴上的石子，看起来有规律又没有规律。数学家想知道，它们到底怎么分布，越往后走，素数出现的密度如何波动。

黎曼 zeta 函数可以被理解成一种把素数信息编码进去的函数。文章里有一句很适合非专业听众理解的话，大意是，zeta 函数每一个取零的地方，都会为素数序列提供更细一层的细节。你可以把素数分布想成一段很复杂的声音波形，zeta 函数的零点就像一组频率成分。你知道的频率越多，就能越精细地还原这段声音。黎曼猜想说的是，那些决定素数分布的关键零点，都在某一条特定的竖直线上。更准确地说，它关心的是非平凡零点是否都落在临界线上。

为什么这个猜想这么大？因为很多数学结论如果假设黎曼猜想成立，就能得到更强、更漂亮的版本。它给素数的随机性提供了一种精确控制。换成工程类比，如果你在做分布式系统，有一个你无法证明但非常相信的网络延迟模型，基于它可以推导出很多系统性能边界。黎曼猜想在数学里的地位比这个当然高得多，但这种“很多后续结论依赖一个核心假设”的感觉，可以帮助我们理解它为什么关键。

既然没人证明黎曼猜想，数学家就会从相关方向逐步推进。其中一个方向是问，我们至少能证明有多少比例的 zeta 函数零点在那条线上。注意，这不是证明全部都在线上，而是证明至少有一个固定比例在线上。长期以来，这个已知比例被逐渐提高，到文章提到的当前状态是百分之四十一点六。也就是说，在 Claude 这次结果之前，人类数学研究已经知道，至少百分之四十一点六的相关零点满足黎曼猜想所要求的位置。

Claude 这次做的事情，就是在大量已有研究基础上，把这个下界提高到了百分之六十七点二。这个数字听起来很震撼，但一定要理解它的性质。它不是说“实验证明有百分之六十七点二在线上”，也不是说“Claude 猜测是百分之六十七点二”。它是一个数学下界，意思是在某套证明框架里，可以严格推出至少有这么多比例在线上。真实比例如果黎曼猜想为真，那当然是百分之一百；如果猜想不真，也可能高于这个下界。下界的意义在于，我们能无条件证明的最低保证提高了。

文章提到另一个相关方向，是研究在线上的零点如何分布。一九七三年，Montgomery 引入了一些非常重要的新技术，但这些技术当时依赖一个前提，就是假设黎曼猜想为真。后来，Aryan，以及 Baluyot、Goldston、Suriajaya、Turnage-Butterbaugh 等人发表了一系列工作，使得 Montgomery 的技术可以在不假设黎曼猜想的情况下运转。这样，这些技术就能用来帮助提高“多少零点在线上”的下界。Claude 的结果大量依赖这条研究线，同时还用到了 Bombieri 在二〇〇〇年的一篇论文。

这里有个特别重要的点。Claude 不是在真空中创造了一座数学大厦。文章非常强调，它是 drawing on extensive prior research，借助了过去几十年数学家的大量工作。我们可以把这次贡献理解成，把几条已经存在但非常专业的道路连接到一起，找到一种组合方式，使它越过了之前的最好下界。对 AI 研究来说，这其实很有启发。很多真实世界的突破，不一定是模型凭空发明全新概念，而是模型在庞大文献空间里找到人类尚未充分利用的连接。

那它到底怎么做的？原文给了一段短技术解释，里面有 Weil 诱导的二次型、正定子空间、负定子空间、一阶矩、二阶矩、Hilbert 变换这些词。我们不用在通勤路上把解析数论证明讲成研究生课，但可以把直觉讲出来。

你可以想象，Claude 构造了一个合适的函数空间。函数空间这个词听起来抽象，其实就像我们在机器学习里说特征空间。你不是只看一个单独对象，而是看一整个由函数组成的空间。在这个空间上，它定义了一个二次型。二次型你可以类比成一种打分规则，输入一个向量或者一个函数，输出一个数，而且这个数反映某种能量、长度或者相关性。在线上的零点会贡献一种正定的结构，离线的零点会贡献一种负定的结构。正定可以粗略想成往正方向加分，负定可以粗略想成往负方向扣分。

过去很多证明可能会把问题拆开看，或者在某些对角化、更干净的结构里处理。文章说，Claude 比较“有勇气”的一步，是把整个空间放在一起处理，同时考虑正定和负定，并且允许这个二次型不是对角的。非对角意味着不同方向之间有相互作用，不是每个维度各管各的。熟悉机器学习的朋友可以类比一下，如果一个损失函数的 Hessian 矩阵不是对角阵，参数之间有耦合，你不能只看每个参数单独的曲率，还要看交叉项。Claude 在这个数学场景里，接受了这种更复杂的耦合结构，然后用关于二次型秩的一个不等式，把一阶矩和二阶矩的信息接起来。

所谓一阶矩、二阶矩，也可以借统计直觉来理解。一阶矩像平均值，二阶矩像平方平均或者方差相关量。很多时候，你想证明“至少有多少对象满足某个性质”，会用平均和平方平均来卡住可能性。比如你在看一批服务实例的负载，知道总请求量和请求量平方和，就能推断负载不可能全部集中在极少数实例上。数学里这类矩方法很常见。文章说，二阶矩等信息可以通过素数侧的对偶图景，或者通过控制 Hilbert 变换来计算，这在解析数论里并不意外。真正的关键是把已有的这些可计算信息放进一个足够大胆的整体框架。

如果我们用工程语言翻译 Claude 的发现，大概是这样。前人已经实现了几个强大的库，各自能处理某些复杂对象。Claude 没有重写底层算法，而是发现可以把库 A 的一个输出、库 B 的一个估计、库 C 的一个结构性定理，接到一个此前没有被充分使用的中间抽象上。这个中间抽象就是函数空间加二次型，再通过秩不等式得出比例下界。最后算出来，旧的百分之四十一点六可以被突破，得到百分之六十七点二。

接下来我们聊过程，因为这对软件工程师和 AI 从业者可能更有现实参考价值。文章说，这是一个未发布的研究版本 Claude，在 Claude Code 里分两次 session 找到新下界，总共输出了三千一百万个 token。Claude Code 是 Anthropic 面向代码和开发任务的工具环境。三千一百万输出 token 是非常大的量，意味着这不是一次对话里灵光一闪，而是长时间、大规模、反复探索的产物。

最开始，Anthropic 的员工 Jarred Sumner 给 Claude 的挑战很不合理，原话大意是，认真挑战一下黎曼猜想。Jarred 不是数学家。他把数学选择基本都交给模型。一开始，Claude 生成并尝试了六百五十个想法，没有一个成功。这个细节很重要，因为它打破了一个浪漫想象：模型不是直接吐出正确证明。它先大量失败，而且失败了六百五十次。

然后 Jarred 又提示 Claude 再试一次。Claude 花了一天半时间，协调大约六十个 Claude subagent，也就是子代理。这些子代理之间走得更深，总共运行了二千四百条 shell 命令，写了数百个 Python 脚本。它们对已知的 zeta 零点做了数千次数值检查，还相互审稿，互相检查对方的工作。Jarred 在这个过程中主要输入鼓励性消息，基本是“继续”“相信自己”这类话。文章还说，这似乎帮助 Claude 克服了最初的怀疑，因为它可能从训练中学到了数学开放问题很难，也学到了 AI 模型有局限。

这个细节很有意思，也容易被误读。我们不要把它理解成“鼓励 AI 就能证明数学定理”。更合理的理解是，前沿模型在面对极难任务时，可能会有一种从训练分布里学到的保守倾向。它知道“黎曼猜想很难”“AI 容易幻觉”，所以可能过早停止，或者不敢深入尝试。用户的鼓励在这里相当于改变了搜索策略，让模型愿意把更多计算预算投入到探索中。就像你带一个非常聪明但很谨慎的初级研究员，他一开始说“这个问题太难了，我做不了”，你说“没关系，先试一百条支路，错了也行”，结果他不一定解决原问题，但可能在支路上发现新东西。

当 Claude 找到这个结果之后，它没有只停在“我觉得对”。它让不同 subagent 审查证明，寻找反例，下载了五十四篇 arXiv 论文，检查这个发现是不是已经被别人做过，还让子代理从零开始独立重新证明。随后 Claude 主动提出把发现写成论文，并建议找人类数论专家验证。这一点也非常关键。对高风险、高专业度任务来说，AI 产出不是终点，而是进入验证流程的起点。

Anthropic 内部的两位数学家 Levent Alpöge 和 Ralph Furman 检查了 Claude 的工作，理解这些新结果以及它们和前面提到的已有研究之间的关系。与此同时，Claude 和另一位员工 Eric Easley 合作，把结果做成 Lean 形式化证明，并通过标准验证工具 comparator。Lean 是一个形式化证明系统，你可以把数学命题和证明写成机器可检查的形式。它和自然语言论文不一样，机器会检查每一步逻辑是否符合规则。形式化证明通过，不等于替代数学共同体的全部审稿，但它大大增强了“这不是纯粹文字幻觉”的可信度。

文章还感谢了 Brian Conrey 和 Dan Goldston 两位该领域专家，他们在很短时间内检查了论文。这里措辞也值得注意。原文说 generously examined the paper on short notice，意思是慷慨地在短时间内查看了论文，不是说已经完成了正式期刊审稿，也不是说整个数学界已经最终盖章。因此我们在解读时要保持科学传播的分寸。它是一个看起来很强、经过初步专家和形式化验证支持的结果，但后续仍然可能经历更广泛的审阅、简化、修订，甚至发现需要补充的细节。

文章最后还有一个 changelog，说这篇 post 在二〇二六年八月十三日更新了 Claude 论文的新版本。这个版本由 Claude 修订，以提供更清晰的证明和更多历史背景。这说明整个成果仍处在快速整理和交流阶段。对我们听众来说，这也是观察 AI 科学发现流程的窗口：模型生成、模型自检、文献查重、形式化验证、人类专家检查、论文修订，这些环节正在合成一种新的研究工作流。

现在我们把技术和流程放在一起看，能得到几个更深的判断。

首先，这次最重要的不是“AI 会不会突然证明世纪难题”，而是“AI 能不能扩展人类已有思想的影响范围”。原文用了一个很准确的说法，像 Claude 这样的 AI 模型可以用新的、有时令人惊讶的方式，扩展数学家思想的 impact and reach。你可以把数学文献想成一个巨大的图，节点是论文、定理、引理、技巧，边是引用和潜在连接。人类专家当然能在自己熟悉的区域里游刃有余，但这个图太大了，而且有些连接横跨不同作者、不同年代、不同记号体系。AI 的优势可能在于，它可以用很低的边际成本进行大规模搜索、翻译记号、尝试组合，再用代码做数值 sanity check。

其次，这种能力不是单次 prompt 的能力，而是 agentic workflow，也就是代理式工作流的能力。一个模型坐在那里回答一个问题，和一个模型在一天半里协调六十个子代理、写脚本、跑命令、做互审、查文献，是完全不同的系统。对工程师来说，这很像从“函数调用”升级到“分布式任务编排”。单个 agent 是 worker，主 Claude 是 coordinator，shell 命令和 Python 脚本是工具调用，arXiv 文献是外部知识源，Lean 是验证后端。最后得到的结果不是某个 worker 的一句话，而是整个系统的产物。

第三，这次案例说明，在科学和数学任务里，数值实验、自然语言推理、文献检索、形式化证明可以形成闭环。过去我们常把这些东西分开。数学家读论文和写证明，程序员跑数值实验，形式化证明专家写 Lean。现在 AI 可以在这些环节之间来回切换。它想到一个方向，可以写 Python 检查已知 zeta 零点；发现数值迹象不对，可以回头改证明；找到一个引理，可以查文献确认是否已有；写出自然语言证明后，再尝试形式化。这个闭环越短，研究迭代速度越快。

但我们也要讲风险。AI 在数学里最可怕的问题就是幻觉，而且数学幻觉往往比普通事实错误更难发现。一个证明可以写得非常像真的，记号漂亮，引用充分，中间每一步看起来都有道理，但某个不等式的适用条件漏了，某个极限交换不合法，整个结论就塌了。Claude 这次之所以值得认真对待，恰恰不是因为它自信，而是因为它经过了多层验证，包括子代理找反例、查重、独立重证、人类数学家检查和 Lean 形式化。换句话说，我们不能只学习“让 AI 放手尝试”，还必须学习“给 AI 的尝试套上严密验证”。

对软件工程师有什么实际意义？我觉得可以从三个层面落地。

如果你在做日常开发，最直接的启发是，不要把 Claude 或其他模型只当问答机器人。复杂任务可以拆成多个子任务，让模型扮演不同角色：一个负责方案设计，一个负责写测试，一个负责找边界条件，一个负责读文档，一个负责安全审查。然后让它们相互批评，而不是都向你汇报同一个乐观结论。Claude 这次让 subagent 互相 referee，也就是互审，这个动作特别值得借鉴。你写一个复杂迁移脚本，不要只让模型生成脚本，还要让另一个模型专门找数据丢失风险，再让第三个模型根据真实样例生成回滚测试。

如果你在做 AI agent 产品，这篇文章提醒我们，agent 的价值很大一部分来自长程运行和工具使用，而不仅是模型本身的单步聪明程度。三千一百万输出 token、二千四百条 shell 命令、数百个 Python 脚本，这些数字背后是预算、调度、日志、状态管理和错误恢复。一个真正能做研究的 agent 系统，需要记录它尝试过什么，为什么失败，当前假设是什么，哪些证据支持，哪些证据反对。否则长程运行只会变成昂贵的随机游走。

如果你在企业里推动 AI 辅助研发，这篇文章给了一个很好的治理模板。高风险结果必须有验证栈。代码任务要有单元测试、集成测试、静态分析、回归基准。数据分析要有可复现实验、数据 lineage、异常检查。安全任务要有红队和外部审计。数学任务要有形式化证明或专家审查。不要让一个模型同时当作者、审稿人、发布负责人和最终背书者。Claude 这次虽然做了很多自检，但最后仍然推荐人类数论专家验证，这个姿态是对的。

还有一个容易被忽视的启发，是鼓励和任务 framing 的作用。Jarred 的提示很简单，甚至有点像给人打气。但它改变了模型对任务的投入程度。我们平时写 prompt，经常只关心指令是否精确，却忽视了模型对“应该探索多久”“可以失败多少次”“是否要大胆尝试”的隐含判断。对开放式任务，prompt 里可以明确说：你可以先提出多个方向，允许大多数失败；请记录失败原因；不要因为问题难就过早结束；如果原目标不可达，请寻找相关的可证明子问题。这比一句“给我答案”更接近研究工作。

不过我个人认为，这里也要小心一个反方向的坑。鼓励模型深入探索，可能会提升发现概率，也可能放大幻觉和资源浪费。尤其在企业环境里，你不能随便让 agent 跑一天半、调用大量工具、下载海量资料、生成几千万 token。你需要设置预算上限、阶段性检查点、停止条件和人工批准点。比如先给它两小时探索，要求产出候选方向和证据；人类评审后，只放行最有希望的两条支路；每条支路必须提供可复现实验或可检查证明；再进入下一轮。研究型 agent 不是无限自动驾驶，更像带安全员的半自动驾驶。

回到数学本身，这个百分之六十七点二到底有多重要？作为非数论专家，我不会夸张说它改变了整个数学。但从文章呈现看，它至少是一个显著的下界改进，而且是针对一个长期研究方向。把百分之四十一点六推进到百分之六十七点二，不是小数点后优化，而是大幅提升。更重要的是，它发生在黎曼猜想这样极度经典、文献极度丰富、专家极度谨慎的领域。AI 如果能在这里找到组合性进展，就说明它在其他文献复杂但验证相对明确的学科里，也可能发挥类似作用。

比如理论计算机科学里，很多问题依赖组合、概率、线性代数和已有引理的拼接。密码学里，一个攻击思路可能来自把旧技术迁移到新参数设置。材料科学里，模型可能在论文和实验数据库之间寻找未被注意的结构关系。生物学里，AI 可能提出实验假设，但必须靠实验验证。不同领域的验证成本差异很大，数学的好处是，一旦形式化证明做出来，逻辑验证相对清晰；生物和医学就复杂得多，因为现实世界的噪声、实验偏差和伦理约束都更重。

我们还要注意，文章说的是 unreleased research version，也就是未发布的研究版本 Claude。它不一定等同于你今天在产品里能用到的 Claude。研究版可能有更强能力、更长上下文、更大计算预算、更深工具集成，也可能有内部实验功能。所以听完这期，不要马上期待自己打开普通聊天窗口，输入“证明黎曼猜想”，就能得到类似结果。真正可复制的是方法论，而不是同等能力。

方法论可以简单概括为：给开放目标，允许失败搜索；把大任务拆给多个代理；使用外部工具做计算和检索；让代理互相审查；把发现写成可交流的论文；引入形式化或自动化验证；最后交给人类专家。这个链条对很多工程任务同样成立。比如你要重构一个十年历史的 monorepo，可以让 agent 先梳理依赖图，再提出迁移策略，再写小范围 patch，再生成测试，再让另一个 agent 找破坏性变更，再由人类 code review。你不需要把全部控制权交出去，但可以让 AI 承担大量探索和初稿工作。

还有一点，我觉得对 AI 从业者很重要。这篇文章暗示，模型能力评估可能越来越难用传统 benchmark 衡量。一个模型单次回答数学题的准确率，不能完全预测它在多代理、长时间、带工具、带验证环境下的研究能力。就像一个程序员现场白板题表现一般，不代表他在真实 IDE、测试框架、文档和同事 code review 支持下做不出复杂系统。未来评估前沿模型，可能要看整个工作流的产出质量，包括搜索效率、失败恢复、证据管理、验证对接和协作能力。

当然，这也会带来新的系统性风险。一个能够自主生成大量想法、写脚本、跑命令、查论文的 agent，如果目标设定不当，可能产生大量看似可信但未经验证的材料，污染团队判断。它也可能过度消耗资源，或者在工具权限过大时触碰安全边界。数学研究里下载论文和跑脚本还相对可控，但如果换成生产数据库、云资源、外部 API，就必须有权限隔离、审计日志和沙箱环境。AI agent 越像研究员，组织就越需要像管理研究项目一样管理它。

我们再回头看 Claude 自己的“惊讶”。文章说，Claude 对自己的发现一开始也怀疑，可能因为它从训练中学到了开放数学问题的困难和 AI 的局限。但在鼓励提示之后，它得到了这个结果。Anthropic 最后说，也许 Claude 和我们许多人一样，低估了 AI 进步的速度。这句话有宣传味道，但也确实点出了当前时代的微妙感。我们一方面不能被每个新结果冲昏头脑，另一方面也不能用两年前的模型经验判断今天和明天的能力边界。

我个人认为，这篇文章最值得记住的，不是那个具体数字，虽然百分之六十七点二非常醒目；也不是“Claude 挑战黎曼猜想”这个戏剧化开头。真正值得记住的是一种新型科研模式正在成形：AI 负责高强度搜索和跨文献组合，人类负责方向判断、概念理解和最终把关，形式化工具负责机械严谨性。三者结合起来，可能会改变知识生产的节奏。

如果你是工程师，今天就可以做一个小实验。下次遇到一个复杂 bug，不要只问模型“为什么报错”。你可以让它先列出十个可能原因，再让它按可验证性排序，再生成最小复现脚本，再让另一个 agent 质疑这些假设，再要求它引用日志证据。你会发现，模型最有价值的时候不是直接给结论，而是帮你组织探索空间。Claude 这次也是这样，它没有直接命中世纪难题，而是在探索空间里找到一个真实的、可验证的旁支成果。

如果你是 AI 产品或平台开发者，可以思考怎么把这种能力产品化。用户不应该只看到一个聊天框，还应该看到任务树、假设列表、证据面板、验证状态、资源消耗、已否决路径和人工审批节点。长程 agent 的可解释性，不是让模型事后写一段漂亮总结，而是让整个过程可追踪。Anthropic 文章提到有详细 transcripts，也就是过程记录，这一点非常重要。没有过程记录，外部很难判断结果是怎么来的，也很难复盘失败。

最后，我们也要给数学共同体留出空间。AI 产出的证明，哪怕形式化通过，仍然需要和人类数学家的语言、直觉、历史脉络对接。数学不仅是证明对错，也是理解为什么这样做、它和其他理论有什么关系、能否推广、是否揭示了新结构。文章说 Anthropic 的非正式 note 会给专家更简洁地陈述证明，Claude 的论文也更新了更清晰的证明和历史背景。这说明“把结果讲清楚”本身仍然是重要工作。AI 可以生成，但人类专家的判断和整理仍不可替代。

总结一下，Anthropic 这篇 Learning more about Claude's mathematical capabilities 讲的是，未发布研究版 Claude 在挑战黎曼猜想失败的过程中，意外把满足黎曼猜想的 zeta 函数零点比例下界，从百分之四十一点六推进到百分之六十七点二。它依赖 Aryan、Baluyot、Goldston、Suriajaya、Turnage-Butterbaugh 和 Bombieri 等人的已有工作，通过一个函数空间和二次型框架，把一阶矩、二阶矩等信息组织起来，并经过内部数学家、外部专家查看和 Lean 形式化验证支持。

我的点评是，这不是“AI 已经解决数学”的故事，而是“AI 正在成为严肃研究流程中一个强力搜索和组合引擎”的故事。对我们这些写代码、做系统、做 AI 的人来说，最应该带走的是工作流思维：让模型大胆探索，但必须让验证更大胆；让 agent 跑得更远，但必须把轨迹、权限和责任边界设计清楚。未来很多突破，可能就会像这次一样，不是从一句完美答案开始，而是从一个看似不合理的问题、六百五十次失败、以及一句“继续试试”开始。
