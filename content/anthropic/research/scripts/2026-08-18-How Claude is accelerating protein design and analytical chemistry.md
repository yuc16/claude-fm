这期值得听，是因为它不是那种只在 benchmark 上刷分的 AI 新闻。Anthropic 讲了两个更接近真实科研流程的例子。一个是让 Claude 去从零设计可以黏住目标蛋白的小蛋白 binder，并且送到外部湿实验室验证。另一个是让 Claude 直接读化学仪器吐出来的原始文件，处理 N M R 和液相色谱质谱联用数据，判断一个化合物到底是不是想要的东西、纯度是多少。对我们做软件、做 AI 的人来说，这篇文章真正有意思的地方在于，它展示了大模型正在从聊天助手，变成能够调工具、跑计算、做校验、写报告的科研 agent。这里的 agent，可以理解为能自主规划任务并调用外部工具的智能体。

先把大背景放一下。过去几个月，AI 辅助发现的节奏明显变快。文章开头提到，数学这类验证相对快的领域已经出现了很多进展，比如一些几十年没解决的 Erdős 问题正在被 agent 一个个推进，Anthropic 之前也分享过 Claude 在黎曼 zeta 函数相关问题上改进一个长期下界的结果。数学问题有一个特点，答案对不对，通常可以通过证明或者形式化验证来检查。哪怕发现过程很复杂，验证链条也相对短。

但生命科学和实验化学不一样。你在电脑里设计出一个分子，不代表它真的能合成，不代表它能稳定存在，也不代表它在水里不会团成一坨，更不代表它进了细胞或者动物体内能有预期效果。实验验证要花钱、花时间，还要依赖仪器、试剂、供应链和实验人员。药物研发尤其是这样，早期发现只是很长链条的一小段，后面还有优化、毒性、药代、临床、监管和生产。Anthropic 在文中也很明确地说，加速早期蛋白设计和化学分析，只是端到端加速药物开发的一部分，很多瓶颈其实来自政策、运营和流程，而不只是核心科学能力。

这篇文章的第一个主角，是蛋白质 minibinder。minibinder 可以翻译成小型蛋白结合物。你可以把它想象成一把很小的、专门定制的钥匙，它要贴到某个目标蛋白表面一个特定的位置。很多现代药物的工作机制，本质上就是绑定。它们绑定到某个蛋白上，然后阻断它、激活它，或者把某个东西送过去。我们熟悉的抗体药、小分子药，背后都离不开这种“找到目标并贴上去”的逻辑。

从头设计蛋白 binder，英文叫 de novo design，意思不是从自然界里找一个现成蛋白来改，而是从零开始设计一个新的蛋白序列和结构，让它能够折叠成你想要的形状，并且贴到目标蛋白上。这个任务很难。因为蛋白质不是乐高积木那么简单。它是一串氨基酸，折叠之后形成复杂的三维结构。你改一个氨基酸，可能局部更好，也可能整个结构塌掉。你设计了一个看起来很漂亮的界面，湿实验室一测，可能根本不表达，或者不溶，或者黏到自己身上，或者什么都黏，完全没有特异性。

过去几年，机器学习确实让蛋白设计快了很多。领域里已经有专门的结构设计模型、序列设计模型、共折叠模型。共折叠模型可以理解为，它不是只预测一个蛋白自己怎么折，而是把目标蛋白和候选 binder 放在一起，预测它们结合后的复合物结构。但是文章强调，这些专业模型虽然强，仍然需要计算专家花几天甚至几周去编排流程。你要选靶点上的结合位点，要生成骨架，要设计序列，要反复筛掉不稳定、不新颖、不多样、不容易表达的候选，还要准备文件送实验室。也就是说，真正难的不只是某个模型，而是一整条科研流水线。

Anthropic 这次做的是一个多分支的蛋白设计 campaign。campaign 在这里可以理解为一轮完整的设计活动。他们用了 Claude Opus 四点八 和 Mythos Preview，针对十五个靶点设计 protein binder。外部评估方是 Adaptyv Bio 和 Twist Bioscience，它们独立把 Claude 的设计生产出来，并在实验室里测试。结果是，十五个靶点里，Claude 在十四个靶点上成功设计出了 binder。至少六个靶点上出现了高亲和力 binder，至少四个靶点上达到了或者超过了此前公开报道的最好亲和力。

这里有两个指标要解释一下。一个叫命中率，也就是你设计的一批候选里，有多少最后真的能绑定。文章说，现在典型的蛋白设计 campaign，命中率大概是百分之十到百分之十五。而 Claude 在所有靶点一起设计的多靶点模式下，Mythos Preview 的总体命中率是百分之二十六点七，Opus 四点八 是百分之二十二点六。另一个指标叫亲和力，也就是绑定有多紧。高亲和力通常意味着药物可以用更低剂量起效，副作用和制造成本都有可能下降。文中对高亲和力的定义，是平衡解离常数达到个位数纳摩尔或者更好。你不需要记这个物理化学细节，只要记住，数值越能体现“贴得牢”，早期药物设计里就越有价值。

Anthropic 还问了一个很合理的问题。如果让 Claude 一次面对十五个靶点，是不是有点像让一个工程师同时维护十五个服务，注意力被分散了？真实的蛋白工程师通常会一个靶点一个靶点深入做。于是他们又跑了单靶点模式，每个 session 只处理一个靶点，各个靶点并行跑。结果 Mythos Preview 在单靶点模式下，总体命中率上升到百分之三十五点一。这个提升很有意思，它说明在复杂科研任务里，模型能力不是一个抽象分数就能概括的。任务组织方式、上下文结构、时间预算、工具调用方式，都会影响最终结果。

我们再看他们具体怎么跑。Anthropic 给 Claude 一个很长的蛋白设计 prompt，大约三万 token。token 可以理解成模型处理文本的基本单位。他们还给了互联网访问、论文等资源语料、Google Drive、Slack、Gmail、BioRxiv 这些连接器，以及可以运行专业蛋白设计和折叠模型的 GPU。多靶点模式给了四十八小时墙钟时间，最多一万二千五百个 NVIDIA H 一百 GPU 小时。单靶点模式给每个靶点二十四小时墙钟时间，最多二千五百个 H 一百 GPU 小时。这里的墙钟时间就是现实世界经过的时间，不是 CPU 或 GPU 累计时间。

关键点是，启动之后，人类基本没有继续给科学或者技术指导。人类只做一些访问审批，比如网络访问请求、代码执行请求，以及处理基础设施问题，保证 session 跑得下去。Claude 自己要做完整流程。它要决定目标蛋白表面哪里值得设计 binder，要调用结构设计、序列设计和共折叠模型生成候选，要做多轮计算机内优化，还要筛选新颖、多样、可表达、可溶、可能绑定的候选。换成软件工程类比，这不是让模型写一个函数，而是让它当一个临时项目负责人，读文档，选方案，调第三方库，跑 batch job，看日志，改参数，最后交付一批可以上线前测试的构件。

每个靶点，Anthropic 要求 Claude 设计三十个 binder。最后他们总共测试了一千三百二十个设计，得到三百五十四个针对十四个靶点的 binder。文章特别提到，这对公开的从头蛋白设计语料也是一个不小补充。因为此前两个比较大的公开集合，加起来大约是四十个靶点、五千七百个设计里有七百七十个 binder。也就是说，这次不仅是在说“模型很厉害”，还确实产生了一批可以进入社区资料库的实验数据。

文中举的第一个代表例子是 RBX1。RBX1 是一个小蛋白，参与驱动特定调控蛋白的靶向降解。对于 Adaptyv Bio 曾经办过竞赛的靶点，Claude 的表现达到或者超过了顶尖参赛者。针对 RBX1，Mythos Preview 在单靶点模式下命中率达到百分之四十，而当时参赛者的命中率是百分之三点七。它排名最高的设计还是一个高亲和力 binder，并且超过了那场竞赛的获胜设计。那场竞赛里一共有二百四十五个参赛设计。这个对比很直观，像是你让模型参加一个真实工程竞赛，它不仅提交了能跑的方案，而且在关键指标上超过了冠军。

第二个例子是 TNF 阿尔法。这个靶点更有现实药物意义。TNF 阿尔法是免疫系统释放的信号蛋白，会触发炎症。阻断 TNF 阿尔法，是一些影响巨大的药物的治疗基础，文章举了 Humira 这个例子。难点在于 TNF 阿尔法有多聚体结构，设计 binder 要瞄准两个蛋白形成的沟槽位置，而不是一个平坦简单的表面。很有意思的是，这个靶点上成功的是 Opus 四点八，而不是整体更偏科学探索的 Mythos Preview。Opus 四点八 设计出了多个 binder，其中一些还能跨物种绑定人、食蟹猴和小鼠的 TNF 阿尔法。跨物种绑定对于动物实验很重要，因为你不能只在人类蛋白上好用，到了小鼠模型就完全没反应。

Anthropic 也坦诚说，他们并不知道为什么 Opus 四点八 在这个靶点上成功，而 Mythos Preview 没有成功。这一点我个人认为特别值得 AI 从业者注意。我们经常会把模型能力想象成单调排序，比如新模型一定在所有任务上更强。但真实复杂任务里，不同模型的训练数据、推理习惯、工具调用风格、探索策略都可能导致局部差异。一个总体上更弱的模型，在某个非常具体的任务上超过更强模型，并不奇怪。这和我们平时做系统也像，某个老版本服务在特定负载下反而更稳定，不能只看总分。

第三个技术点，是 Claude 设计出了含有 β 折叠结构的 binder。多数计算设计的 binder 是 α 螺旋束。α 螺旋可以想象成卷起来的弹簧，在蛋白设计里相对更容易控制。β 折叠则是一些伸展的氨基酸链要并排对齐，像一排排纸带靠氢键连接。它更容易折错，也更容易聚集。聚集就是蛋白分子没有各自保持正确折叠，而是互相粘在一起。文章说，Claude 在六个靶点上设计出了十五个已确认 binder，其中至少百分之二十是 β 链结构。这说明它不是只会套一种简单的 α 螺旋模板，而是在一定程度上能处理更复杂的蛋白结构逻辑。

当然，也有失败和局限。文章提到 BBF 十四和麦芽糖结合蛋白 MBP。BBF 十四本身是一个从头设计出来的 β 桶形蛋白，不存在于自然界，正因为它新颖，所以常被用来做 binder 设计 benchmark。Claude 对 BBF 十四还是做出了三个独立 binder，每个设计分支一个，骨架还不同，但亲和力只是亚微摩尔到微摩尔级，算是中等或者一般。MBP 就更难。它是一个大的、柔性的细菌蛋白，表面光滑而且亲水，适合做实验试剂，但这也意味着 binder 很难找到可以抓住的“把手”。Claude 针对 MBP 的九十个设计里，没有一个被确认绑定，只有一个表现出弱而可重复的绑定信号。

这部分结果的正确读法，不是“Claude 已经解决蛋白设计”，而是“Claude 能够在一个真实但受控的早期设计流程中，自动化执行大量专家工作，并且实验结果相当强”。Anthropic 也说，他们还计划做更广泛的表征，来进一步确认命中率和亲和力测量。蛋白实验里，初筛结果和深入表征之间还有距离。比如你可能要测更精确的结合常数，要确认是否特异，要看结构是否真像模型预测的那样，还要评估表达量、稳定性、免疫原性等一堆药物化指标。

这里还必须讲安全。蛋白设计和其他研究生物学能力具有明显双重用途。它们可以帮助开发疗法，也可能被坏人用于危险研究，比如生物武器相关工作。Anthropic 在文中说，他们正在通过可信访问项目安全交付这些能力，同时蛋白设计等双重用途研究生物能力在一般访问的最强模型中仍不可用。文章也提到，目前生命科学研究任务在他们最强能力模型里是 blocked 的，也就是被限制的。他们的高优先级之一，是推出面向科学家的访问项目。对我们这些普通用户来说，重点是不要把这类能力想象成一个随便开放的 API 功能。越接近真实实验能力，越需要访问控制、审计和责任边界。

讲完设计新分子，文章的第二个实验是解释已经做出来的分子。这里进入分析化学。化学家每次合成一个分子，都必须确认两件事。第一，它是不是我想合成的那个东西。第二，它有多纯。因为反应可能不完全，可能有副产物，可能有溶剂残留，也可能看起来像成功其实结构错了。这个确认过程在合成化学里非常日常，也非常耗时间。

第一种常用技术是核磁共振 spectroscopy，简称 N M R。文章这里主要讲的是质子 N M R，也就是看氢原子的谱。你可以把 N M R 谱想象成一串山峰，每个峰对应分子里某个氢，或者一组等价氢。峰的位置告诉化学家这个氢大概连在什么化学环境上，峰的面积告诉你它代表多少个氢。化学家要把谱图上的每个峰，和候选结构里的每个原子对应起来。对于复杂一点的小分子，这个过程并不轻松，很像你拿到一份没有注释的性能火焰图，要根据经验判断每个峰到底属于哪个函数调用。

第二种技术是液相色谱质谱联用，也就是 L C M S。它先把样品里的不同成分通过柱子分开，哪个先出来、哪个后出来，会形成一条分离曲线。然后仪器用紫外吸收估计每个成分有多少，再测每个成分的分子质量。它主要用来判断纯度和分子量。注意，仪器真正跑一次并不慢。常规质子 N M R 可能两三分钟，L C M S 大约十分钟。麻烦的是后处理。仪器会生成厂商自己的原始文件格式，通常要用厂商软件或者专业软件打开。你要做傅里叶变换、相位校正、基线校正、选峰、积分、出报告。很多时间花在这里。

Anthropic 给 Claude Opus 五 做的测试很直接。他们提供一个合同实验室的原始文件，任务是常规质量控制样品。除了原始 N M R 和 L C M S 文件，只给了很短的自然语言 prompt，没有厂商软件，没有操作员。Claude 在 Claude Science 环境里并行处理，N M R 用了二十三分钟，L C M S 用了十九分钟。结果和实验室自己的分析非常接近。每个峰的氢计数和实验室结果相差在零点零八个氢以内，纯度 Claude 算出百分之九十六点四，实验室是百分之九十六点三三。

N M R 这边，Claude 先把仪器原始信号转换成经过校准的谱图，然后给出十八个峰的表格，每个峰有氢计数。接着它像化学家一样，把四个宽峰标记出来，认为这些峰可能是连在氮或者氧上的氢。为什么这有意义？因为连在氮或者氧上的氢往往会有交换行为，峰形也可能比较宽。Claude 提出了一个标准检查方法，往样品里加重水。重水里的氘会把这些可交换氢换掉，所以相关峰会变小或者消失。巧的是，合同实验室在第一次测量三天后，独立做了同样的检查。

更有意思的是自我纠错。Claude 拿到重水实验的原始文件后，量化数据变化。它第一遍曾经说四个标记峰全都消失了，但自己的自检发现这个说法过头了，实际只有两个消失。最后它得出了和实验室操作员相同的结论。这个细节很重要。科学任务里，模型会不会犯错当然重要，但更重要的是，它有没有机制发现自己的错、回到原始数据重新计算、修正结论。对工程系统也是一样。我们不可能假设 agent 永远不出错，所以要看它能不能产生可检查的中间结果。

L C M S 这边，难度在原始文件格式。文章说，这个仪器文件使用未公开文档的厂商格式。Claude 先搞清楚数据是怎么编码的，然后在真正分析前，先复现仪器自己记录的所有二千六百六十四次扫描总量，以确认读取文件没有错。这个操作非常工程化。它没有上来就画图，而是先做完整性校验。确认读对以后，它给出了化学家会期待的结果，包括分离曲线、质谱和紫外谱、纯度表、化合物分子量，以及一份可以复用的读取此类文件的代码。同时，它还列出结果可信度的 caveat，也就是注意事项。比如这类仪器只能把质量给到最接近的整数单位。

时间对比也值得讲清楚。通常化学家会手动做这些分析。对治疗相关的小分子，每个样品可能要半小时到一小时。文中实验室记录显示，N M R 每张谱的上手处理大约两分钟，L C M S 报告在样品上机后大约两小时出来。但合同实验室的最终报告，是第一次谱图采集后四天才到。这个四天不是说有人连续干了四天，而是现实工作流里样品一个个排队，中间会插入别的工作，要等审核和报告。Claude 的意义在于，它在二十五分钟内并行处理并解释了两个文件，还生成了文字报告。

从这里我们可以抽象出文章真正想表达的能力。Claude 不是凭空知道一个化合物是什么，也不是替代仪器。仪器仍然采数据，实验仍然要做。Claude 加速的是测量之后到可读结论之间的那段劳动。它能读原始文件，写转换代码，做数值校验，产出图表和表格，还能提出下一步实验。对于很多科研团队，这段工作看起来不如发现新药那么耀眼，但非常消耗人的注意力。大量科学时间就是被这些“每次都差不多，但每次又不能随便”的任务吃掉的。

那这篇文章对通勤路上的软件工程师和 AI 从业者意味着什么？我觉得第一个启发是，未来有价值的 AI 系统，很可能不是一个单一大模型 endpoint，而是模型加工具加权限加数据加验证的工作流。蛋白设计实验里，Claude 的角色不是替代所有专业模型，而是编排那些专业模型。化学分析实验里，Claude 的角色不是替代 N M R 或 L C M S 仪器，而是把仪器数据变成可解释结果。这个模式放到软件工程里，就是 LLM 不一定要自己“知道”所有东西，但它要会调用编译器、测试框架、日志系统、监控平台、数据库和文档检索，还要知道什么时候停下来做 sanity check。

如果你今天要在公司里设计类似的 agent 系统，我建议先不要追求“全自动研发”。可以从窄任务开始，最好是有明确输入输出、有历史人工结果可对比、出错成本可控的任务。比如自动处理实验数据、自动生成测试报告、自动审查配置变更、自动分析线上 incident 初稿。然后把每一步拆成可记录的中间产物。Claude 读 L C M S 文件时先复现二千六百六十四次扫描总量，这就是非常好的设计。对应到工程系统，你可以要求 agent 在分析日志前先确认时间范围、服务版本、样本量和缺失字段；在给出根因前，先列出它查询过哪些 dashboard、跑过哪些 SQL、排除了哪些假设。

第二个启发是，prompt 很重要，但 prompt 不是全部。蛋白设计那边给了一个三万 token 的详细 prompt，还给了资源、网络、GPU、文件连接器和充足时间。化学分析那边反过来，只给了两句很短的 prompt，但任务环境里有 Claude Science，可以让模型执行代码、处理文件、生成图。很多时候我们讨论 prompt engineering，容易忽略执行环境。一个只会聊天的模型，即使知道步骤，也没法真正跑傅里叶变换、解析二进制文件、调用 GPU 模型。反过来，一个有工具但没有验证习惯的 agent，也可能把错误结果包装得很漂亮。所以系统能力来自上下文、工具、权限、时间预算和评估闭环共同作用。

第三个启发是，评估一定要接近真实世界。蛋白设计的结果不是模型自己打分，而是外部机构生产并测试。化学分析的结果不是看回复像不像专家，而是和合同实验室的处理结果比氢计数和纯度。对于我们做企业 AI 落地的人，这一点非常关键。不要只看 demo，不要只看回答是否流畅。你要定义能被业务接受的指标，比如误报率、漏报率、处理时延、人工复核节省时间、结果可追溯性。最理想的是像这篇文章一样，有外部或独立流程做验证。

第四个启发是，模型差异要当作工程事实管理。TNF 阿尔法上 Opus 四点八 赢了 Mythos Preview，说明你不能简单地把所有任务都迁到名义最强模型，然后假设万事大吉。生产系统里可能需要多模型路由，或者至少保留回归测试。某些任务上新模型可能更会探索，某些任务上老模型可能更保守。你要建立自己的任务集，持续测，而不是把厂商发布会上的综合能力当成唯一依据。

如果你是做生命科学或者化学相关工具的同学，这篇文章也给了几个可以马上借鉴的方向。对于分析化学，文章最后说得很直接，你可以在 Claude Science 里给 Claude 一个原始 N M R 或 L C M S 文件，让模型确认化合物身份和纯度。当然，实践中我会建议你永远保留人工复核，尤其在数据格式不熟、样品重要、结论会影响下一轮合成或者申报时。可以先把它当作自动预处理和初稿生成工具，让人审它的峰表、积分、纯度和 caveat。等你积累足够内部对比数据，再决定哪些场景可以半自动。

对于蛋白设计，普通用户就不能也不应该随便复现文中的能力。一方面是安全限制，另一方面是实际门槛。你需要专业模型、GPU、湿实验室验证、样品订购、表达纯化和测定流程。更现实的用法，是让 AI 帮你做文献整理、靶点背景分析、已有结构和突变信息汇总、实验计划草稿、数据整理和报告生成。如果你的机构有合规的访问项目和生物安全审查，再考虑更深的设计自动化。不要因为看到“十四个靶点成功”就低估湿实验室和安全治理的重要性。

还有一个坑，是不要把早期 binder 等同于药物。文章自己也提醒，蛋白 minibinder 不是标准治疗药物形态。即使对常见药物形态，比如单克隆抗体和小分子，设计出高亲和力 binder 也只是第一步。一个药物样分子还要看特异性、稳定性、可制造性、体内分布、免疫反应、毒性、给药方式和商业生产。很多候选分子会在后面环节失败。所以这篇文章的意义不是“Claude 五分钟发明新药”，而是“Claude 可能显著压缩早期发现流程中的计算和分析劳动”。

我个人认为，这篇文章最重要的信号，是科学 agent 的价值正在从“给建议”走向“交付可验证产物”。蛋白设计里，产物是一批真实被测的 binder。化学分析里，产物是谱图、表格、纯度、代码和报告。它们都不是完美终点，但都能进入下一步工作流。对 AI 产品来说，这比单纯聊天更接近可定价、可集成、可审计的能力。

当然，我们也要保持冷静。文章来自 Anthropic，自然会展示成功案例。蛋白设计结果还需要更多表征，化学分析也只是一个常规质量控制样品上的实验，不代表所有复杂样品都能一次搞定。模型可能读错文件、过度解释谱峰、忽略杂质，也可能在蛋白设计中找到计算上好看但实验上不稳定的方案。因此，真正的落地不是把人踢出流程，而是把人放在更高杠杆的位置，让模型承担重复、繁琐、可校验的部分，人类负责设定目标、判断风险和做最终确认。

收个尾。Anthropic 这篇 How Claude is accelerating protein design and analytical chemistry，用两个实验说明了 Claude 在生命科学里的两种加速方式。一种是把专业模型和计算资源组织起来，端到端执行早期蛋白 binder 设计。另一种是直接处理仪器原始数据，把化学家的日常分析工作自动化。我个人的点评是，这不是一个“AI 已经替代科学家”的故事，而是一个“AI 开始能当科研流水线里的可靠执行层”的故事。未来真正改变行业的，可能正是这些看起来不酷、但每天都在消耗专家时间的环节被一点点自动化。
