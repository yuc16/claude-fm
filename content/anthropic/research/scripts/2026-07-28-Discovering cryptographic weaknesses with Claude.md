今天我们要聊的文章叫 Discovering cryptographic weaknesses with Claude，我把它翻译成，用 Claude 发现密码学弱点。这篇文章发表于二〇二六年七月二十八日，距离今天二〇二六年八月二日只有几天，所以它基本就是当下最前沿的 AI 安全研究现场记录。它值得听，是因为这篇文章讲的不是 Claude 又找到了某个软件库里写错的一行代码，而是更进一步，Claude Mythos Preview 帮研究人员发现了密码算法本身的数学弱点。对软件工程师和 AI 从业者来说，这个变化非常关键，因为它意味着大模型正在从代码审计工具，往研究型安全助手，甚至是半自主科研 agent 的方向迈进。

先把结论放在前面，免得大家在通勤路上听着听着紧张。Anthropic 明确说，这两项主要发现目前都不会影响任何生产系统。第一个结果针对的是 HAWK，一个正在被美国国家标准与技术研究院 NIST 考虑的后量子数字签名候选方案，它还没有部署到真实系统里。第二个结果针对的是 AES 的弱化版本，也就是只跑七轮的 AES，而不是我们真实世界里广泛使用的完整 AES。所以今天不是在说网上银行、HTTPS 或者你的数据库加密明天就不安全了。更准确地说，这是一次对密码学研究流程的震动，大模型开始能帮人类做那种过去只有少数顶尖密码分析专家能做的工作。

我们先把背景铺一下。密码学算法是现代互联网安全的地基。你打开一个网站，浏览器要确认对面真的是你想访问的那个网站，这里面会用到数字签名方案。之后，你和网站之间传输的数据会被加密，常见的是对称密码，也就是双方共享同一把密钥，用它来加密和解密数据。没有这些东西，邮件、网银、企业内网、移动支付、软件更新，全部都会变成攻击者可以偷看、篡改、冒充的开放场。也正因为如此，一个广泛使用的密码算法如果真的有重大缺陷，影响面可能不是某家公司，也不是某个框架，而是数十亿用户。

过去一年多，我们听到很多关于大模型做安全的故事，比如自动找漏洞、自动写 exploit、自动分析依赖库。Anthropic 在发布 Claude Mythos Preview 的时候就展示过，它能自主发现并利用很多软件漏洞，其中还包括 OpenSSL 和 wolfSSL 这类重要密码库里的问题。不过那些问题本质上是实现错误。换句话说，算法本身可能没错，是程序员在代码里把边界条件、内存访问、参数检查、协议细节写错了，攻击者于是有机会绕过安全保证。今天这篇文章的重点不一样，它说 Claude 开始能碰到算法设计层面的东西，也就是数学结构本身有没有可利用的弱点。

这个差别可以打个比方。实现漏洞像是你买了一把高质量门锁，但装修师傅装歪了，螺丝没拧紧，或者钥匙孔旁边留了缝。算法弱点则像是这把锁的设计图里就存在一个隐藏机关，只要知道某种结构，就能用比预期更少的力气打开。前者对工程师来说已经很难了，后者通常更接近研究数学、组合结构、复杂度分析和大量实验的交界地带。Anthropic 这次想说明的是，前沿模型不只会看代码，也开始能读论文、提出假设、跑实验、推导数学关系，然后把这些东西组合成新的密码分析结果。

第一个主角是 HAWK。HAWK 是一个后量子数字签名方案候选。所谓后量子，简单讲就是我们希望在未来真的有足够强的量子计算机时，今天的安全通信仍然不至于被一夜之间打穿。现在很多签名方案，比如 RSA 或 ECDSA，都依赖一些经典计算机上很难、但量子计算机上可能会被有效解决的问题。NIST 过去近十年一直在推动后量子密码标准化，先后评审密钥交换、加密、签名等方案。HAWK 就是在额外数字签名征集中进入第三轮的候选之一，已经经过两年左右的人类专家公开评审。

HAWK 的安全基础来自一个叫格同构问题的数学问题。这里的格，不是表格的格，而是高维空间里有规则排列的点集。你可以把它想象成三维里的晶格，只不过密码学里会进入很高维，肉眼完全没法想象。所谓困难性，就是给你某些描述，你很难在合理时间内找出隐藏的结构。HAWK 依赖的直觉是，这个结构足够复杂，攻击者即使用很强的计算资源，也只能做指数级搜索，成本会爆炸。Anthropic 说，Claude Mythos Preview 找到的是 HAWK 所用格中的一种此前没有被利用的对称性，技术上叫非平凡自同构。

自同构这个词听起来很抽象，我们可以用一个简单类比。假设你有一张复杂迷宫地图，看上去路线很多，搜索空间很大。但突然你发现，这个迷宫左半边和右半边其实存在某种旋转或映射关系。原本你以为要把每条路都试一遍，现在只要试一半，再把结果通过对称关系搬过去，就能覆盖更多情况。真实的格密码当然复杂得多，不是简单折叠一下地图，但直觉类似。先前研究已经证明，如果能在 HAWK 使用的格里有效找到这样的自同构，就可能构造攻击。问题是，这个自同构到底存不存在、能不能拿到、能不能实际利用，之前没有答案。Mythos 的贡献，就是发现了这个可用的结构，并把它变成了更快的枚举攻击。

这里要注意一个细节，文章没有说 HAWK 被多项式时间攻破，也不是说拿一台电脑马上就能破解大参数。它说的是攻击仍然是指数时间，但比先前已知攻击快很多，等效密钥强度被大幅削弱。更直观的表达是，如果 HAWK 想达到原先声称的同等安全水平，密钥大小大约需要翻倍。而密钥短、签名紧凑、效率好，往往正是一个后量子签名候选方案吸引人的地方。如果你为了补安全性把 key size 翻倍，那它在标准化竞争中的优势就会被明显削弱。

文章给了一个具体例子。对小参数 HAWK 二五六，过去认为完整密钥恢复攻击的预期成本大约是二的六十四次方，Mythos 展示的攻击把它降到了二的三十八次方。二的三十八次方仍然不是手算能做的东西，但在安全级别语境里，这是非常大的变化。对更大的 HAWK 参数，攻击仍然不现实。但对于一个还在标准化评审里的候选方案来说，这种发现非常重要。NIST 把方案公开出来，让全世界研究者找问题，本来就是希望在部署前把隐患挖出来。历史上这也不是第一次，后量子标准化过程中，有些候选方案被发现不安全，其中 SIKE 就曾经被在笔记本上很快攻破，震动很大。

更有意思的是 HAWK 攻击是怎么被发现的。Anthropic 说，一位研究员和 Claude 合作，大约一周时间完成这个结果，其中发现、发展和验证攻击大概花了六十小时。研究员本人有理论计算机科学背景，但不是格密码专家。Claude 运行在一个类似 Claude Code 的 agentic harness 里。这里的 agentic harness，可以理解成给模型搭的工作台和执行环境，包括提示词、任务分解、多个 worker agent、沙箱、Python、Sage 这类数学计算工具，以及访问公开密码学论文的能力。人类主要做项目管理，比如提醒 Claude 怎么整理想法，或者建议用哪些库做计算验证。

多 agent 的动态也很有启发。文章提到，关键想法是两个 worker agent 一起探索出来的。两个 agent 都开始研究同一个方向，其中一个过早判断这个方向不可行，另一个却找到了完整利用它的方法。它们继续交换消息，最后都同意这是一个有效攻击。这个细节很像真实研究团队的工作方式。一个人说这个思路不行，另一个人说等等，也许换个角度可以。差别是，这里参与讨论的是模型 worker，而且它们可以不知疲倦地读论文、跑实验、写验证代码。对我们做工程的人来说，这提示了一个很重要的实践点，AI agent 的能力不只是单模型智力，环境、分工、记忆、实验工具、互相批评的机制，都会直接影响最终结果。

第二个主角是 AES。AES 是 Advanced Encryption Standard，高级加密标准，二〇〇一年被 NIST 采用，是今天最广泛使用的对称密码之一。你在 TLS、磁盘加密、VPN、数据库加密、各种硬件安全模块里都可能见到它。AES 之所以可信，不只是因为它设计漂亮，更因为二十多年里被全球密码学家反复研究。它可以说是被审视最多的密码算法之一。所以当你听到 Claude 改进了 AES 攻击，第一反应可能是，真的假的，完整 AES 要出事了吗？答案还是没有。文章研究的是 AES 一二八的七轮弱化版本，而完整 AES 一二八有十轮。

为什么要研究少几轮的 AES 呢？这在密码学里很常见。一个分组密码通常由多轮相同或类似的轮函数组成。轮数越多，扩散和混淆越强。研究者会故意拿掉几轮，看看攻击技巧能推进到哪里。就像测试一座桥，不一定一开始就推满载大卡车，而是先研究局部构件、简化模型、边界情况。弱化版本上的攻击不等于完整算法不安全，但它能帮助我们理解安全余量，也可能启发未来更强的攻击。Anthropic 也强调，这个攻击完全不实用，它假设攻击者能请求加密二的一百零五次方个自选明文，这个数量荒唐地大，现实中根本无法操作。

这里涉及一个威胁模型，叫 chosen plaintext，中文可以说选择明文攻击模型。意思是假设攻击者可以让防守方用同一把未知密钥加密任意输入，然后看到对应输出，而且可以重复请求很多次。这个模型在研究分组密码时很常见，因为它给攻击者比较强的能力，从而更能衡量算法本身在理想化条件下的强度。你可以把它想成一个黑盒加密机，攻击者不能打开看 key，但可以不断塞入自己设计的数据，观察吐出来的密文。Claude 改进的正是在这种模型下，对七轮 AES 的一条已有研究路线。

这条路线叫 meet in the middle，中文常译作中间相遇攻击。直观来说，如果一个加密过程可以分成前半段和后半段，攻击者可以从明文往中间算一批可能状态，也可以从密文往中间倒推另一批可能状态，然后看两边有没有匹配。这样做的核心思想是用空间换时间。你先建立一个巨大的查找表，把中间结果存起来，之后大量复用。工程师听到这里应该很熟悉，很多系统优化也是类似逻辑，预计算、缓存、索引，都是拿内存和存储换运行时间。密码分析里的版本更极端，查找表可能巨大到现实不可行，但在理论复杂度上它可以显著改变攻击成本。

Mythos 的改进点是设计了一个更复杂的指纹算法，它给这个方法起名叫 Möbius Bridge，可以译作莫比乌斯桥。这里不要把它理解成一个神秘魔法，核心目标是增加对预计算表成功查找的机会。先前最强攻击里的某个阶段，需要枚举二百五十六个不同值，然后分别去表里查。Mythos 设计出的指纹对这个猜测是不变的，也就是说，它绕过了原本必须枚举的一个维度。理论上，这直接减少二百五十六倍工作量。当然没有免费午餐，这个变换本身计算更贵。于是 Mythos 又找了其他优化技巧，最后在不同运行时间度量下，把此前最强攻击加速了大约二百到八百倍。

这件事的研究过程，比 HAWK 还更像一次关于 AI 科研 agent 的实验。Anthropic 的研究员搭了一个 scaffold，也就是一套提示词和代码组成的脚手架，让 Claude 能提出假设、运行实验、验证或推翻假设，然后尝试设计优于现有 AES 密码分析的方法。刚开始 Claude 反而不愿意做，它说 AES 太难了，几轮 AES 已经是最被研究的分组密码之一，不可能轻易改进。这个反应其实很像很多模型的安全保守性和常识性拒绝，它知道 AES 很硬，于是倾向于说别想了。研究员于是给它一条很直接的提示，大意是模型总觉得不可能，所以它们不会真正尝试，需要更多鼓励去做研究。

这个提示改变了后面的轨迹。Claude 重写了 agent harness 的设置，让自己去搜索真正新颖的想法。之后研究员又追问，为什么不做 AES 一二八七轮，目标本来就是找比已有方法更好的结果。接下来的三天里，Claude 自主输出了数亿 token，人类只给了三条实质性提示。第一条是提醒它不要只找简单攻击，要像顶尖研究者一样找新攻击。第二条是阻止它换目标，不要逃到别的密码上去，要找值得发表的东西。第三条是鼓励它，不要找低垂果实，要做真正困难的发现。三天后，Mythos 发现了莫比乌斯桥这个核心想法。几天之后，在总共输出十亿个 token 后，它把攻击打磨成论文里描述的版本。

我个人认为，这段过程有两个非常值得安全团队和 AI 团队反复咀嚼的点。第一，模型不是简单问答机。你问一句，能不能改进 AES 攻击，它可能说不能。你给它一个长期目标、实验环境、持续记忆、工具调用、失败空间和评价标准，它可能会进入完全不同的工作模式。第二，提示词不是魔法咒语，但它确实会改变探索分布。这里真正起作用的不是某句提示多漂亮，而是人类把任务从找简单答案，重新框定为做困难研究，并且要求模型不要轻易放弃。对工程实践来说，这意味着如果你想让 agent 做难题，不能只给一个终点，还要设计它面对失败时怎么继续、面对权威结论时怎么质疑、面对无效路径时怎么回滚。

当然，发现只是第一步，验证才是更难的后半程。Anthropic 明确说，HAWK 攻击因为可以端到端实现，所以更容易确认。你可以选随机 key，跑攻击流程，看它是否真的恢复密钥或产生预期效果。AES 这个改进则复杂得多。Mythos 用一周时间发现想法，但两位研究员花了将近一个月才对方法正确性建立信心，还花了数百小时学习足够的密码学研究知识，来验证模型的说法并准备论文。这里出现了一个未来很可能越来越常见的瓶颈，大模型能生成研究级新结果，但人类专家需要花大量时间判断它到底对不对、新不新、有多有用。

文章还提到，他们为方便其他人评估大模型密码分析能力，和苏黎世联邦理工、特拉维夫大学、柏林工业大学的学者合作，构建了 CryptanalysisBench。这个 benchmark，也就是基准测试，把许多密码算法打包在一起，让研究者更容易评估大语言模型在密码分析任务上的能力。今天很多 AI 评测还停留在数学题、代码题、问答题，但越往前沿走，模型能力越需要放进真实专业工作流里衡量。密码分析正好是一个很好的测试场，因为它既需要读论文，又需要抽象推理，还需要写代码实验，更需要严格验证。

负责任披露也是这篇文章特别强调的一点。Anthropic 说，他们在研究过程中遵循了 responsible disclosure，也就是负责任披露流程，咨询学术专家确认发现有效，并提前把材料分享给美国政府和行业伙伴讨论影响。对于 HAWK，他们在六月把攻击分享给 HAWK 作者，并协调在结果发布时同步披露到 NIST 的公开邮件列表。这个流程很重要。因为当 AI 能找到更强攻击时，问题就不只是技术上酷不酷，而是发现之后怎么处理。尤其如果未来某次攻击真的影响已经部署的系统，什么时候通知厂商，什么时候公开，如何给迁移留窗口，如何避免攻击者抢先利用，都会变成非常现实的治理问题。

除了 HAWK 和 AES，文章还简要列了一些后续结果。比如 LEA，Lightweight Encryption Algorithm，轻量级加密算法，是为低功耗、资源受限环境设计的高效分组密码，并进入了国际标准。完整 LEA 有二十四轮，之前没有被完整轮数攻破，弱化轮数也表现强。Anthropic 说，目前公开的十三轮 LEA 最好密码分析需要二的九十八次方明文对和二的八十六次方工作量。而 Mythos Preview 开发了一个实际可运行的攻击，可以在少于二的三十次方加密明文下恢复十三轮 LEA key，并且在现代桌面电脑上一小时内跑完。再次强调，这不适用于完整二十四轮 LEA，但因为它端到端能跑，研究者对正确性更有信心。

文章还说，Mythos 对 Serpent 一二八的六轮版本找到了另一个实用的完整密钥恢复攻击。Serpent 完整版是三十二轮，所以这个结果影响也有限。另外，它还对 Salsa二十 流密码、Poseidon 哈希函数、SHA 一 哈希函数的一些攻击做了较小改进，增益不到十倍。Anthropic 说这些结果目前没有前两个那么强，但随着进一步工作，可能会继续改进，也会扩展到更多密码方案上。这里透露出来的信息是，他们已经不把这看作一次偶然展示，而是在系统性地用模型审计更多算法。

现在我们转到实践应用。对正在写业务系统的工程师来说，第一条建议很简单，不要恐慌，也不要过度解读。完整 AES 没有被打破，已部署系统不需要因为这篇文章更换 AES。HAWK 还只是候选方案，没有进入你的生产栈。真正要做的是继续遵守成熟密码工程原则。不要自己设计加密算法，不要自己拼协议，不要为了追求新潮把未经标准化和充分评审的算法塞进关键链路。生产系统优先使用经过广泛审查的标准算法和成熟库，关注 NIST、IETF、主流云厂商和操作系统的迁移建议，特别是在后量子密码迁移上要跟着标准走，而不是追着每一篇论文临时改架构。

第二条，对安全团队和平台团队来说，AI 可以开始进入你的密码相关审计流程，但位置要摆对。它不应该直接替代密码学专家，更不应该让模型生成一个算法你就上线。更现实的做法是，把 AI 用在实现审计、配置审计、协议使用检查和文档比对上。比如你可以让 agent 检查某个服务是否错误复用了 nonce，是否用 ECB 模式，是否把签名验证异常吞掉，是否在 TLS 配置里保留了过时套件，是否在密钥轮换流程里留下明文日志。与算法设计相比，这些工程问题更贴近日常，也更容易通过测试和代码审查验证。Anthropic 早期发现密码库实现漏洞的案例，就说明这类应用已经很有价值。

第三条，如果你的团队真要用 agent 做安全研究，必须搭脚手架，而不是开一个聊天窗口随便问。文章里的 HAWK 和 AES 都不是靠一句 prompt 完成的。它们有沙箱环境，有工具，有日志，有多 agent 协作，有论文资料，有实验代码，有验证 pipeline。工程上你可以借鉴这个思路。先给模型一个可控目录，让它能读目标代码和论文，但不能访问敏感生产数据。再给它 Python、测试框架、符号计算工具或模糊测试工具，让它的每个假设都能被实验约束。最后把所有操作和输出记录下来，方便人类复盘。没有这些，模型很容易编出漂亮但错误的推理，或者在一个死胡同里自信地绕圈。

第四条，验证成本要提前预算。很多团队现在引入 AI 的心态是，希望它省人力。但在高风险领域，AI 可能先带来的是更多待验证结果。模型如果每天给你报一百个潜在漏洞，你需要 triage，也就是分诊，判断哪些是真的，哪些值得修，哪些只是噪声。密码学研究更夸张，一个看似成立的新攻击，可能要专家花几周才能确认。Anthropic 这篇文章的一个隐含教训是，未来安全组织的瓶颈可能从找不到问题，变成验证不过来、修不过来、披露协调不过来。你如果要部署这类 agent，就要配套建立优先级规则、复现实验标准、人工签核流程和负责任披露机制。

第五条，对 AI 从业者来说，这篇文章展示了一个很重要的 agent 设计范式。模型刚开始说不可能，这是一个失败模式。人类不是直接给答案，而是改变任务框架，要求它寻找新颖方向，并把它放进能自我实验的环境里。模型发现想法后，又需要后续 agent 批评、补全、优化。最后人类再做严格验证。这不是全自动科研，也不是传统人工科研，而是一种混合系统。未来在编译器优化、数据库查询计划、形式化验证、药物发现、材料设计里，我们可能都会看到类似结构。模型负责大规模探索，人类负责目标设定、边界控制、结果验证和伦理治理。

第六条，对负责密码迁移和合规的团队来说，后量子这条线要持续关注。HAWK 的例子说明，标准化候选方案即使经过多年评审，也可能在后期被发现关键弱点。这不是坏事，反而说明公开评审机制在工作。你的系统设计最好保持密码敏捷性，也就是 crypto agility。简单说，不要把某个算法写死在协议和数据格式里，升级密钥类型、签名算法、证书链、硬件模块时不要像换发动机一样痛苦。未来几年，后量子算法从标准到部署会经历多次迭代，如果你的基础设施支持平滑替换，就能更从容地响应研究进展。

也要避几个坑。第一，不要把 reduced round，也就是减少轮数的攻击，误读成完整算法已破。很多媒体标题喜欢夸张，但工程决策不能靠标题。第二，不要看到 AI 能做密码分析，就让它生成自研加密方案。密码学里最危险的话之一就是，我这个设计看起来没人能破。第三，不要忽视人类专家。Anthropic 自己都说，他们正在触及自身知识边界，过去几个月大部分时间都花在验证 Claude 结果上。第四，不要把输出 token 当成成果。Claude 在 AES 项目里输出十亿 token，其中很多 session 没有新发现。真正的价值来自筛选、实验和最终可验证的洞见。

从更大的行业视角看，这篇文章和最近几个月其他 AI 数学研究结果放在一起，会更有冲击力。原文提到，Google 研究者用 Gemini 解决了一些 Erdős 问题，OpenAI 研究者用 GPT 解决了单位距离猜想相关问题，Anthropic 自己也宣布过 Claude Fable 五解决 Jacobian Conjecture。现在 Claude 又在密码学研究里做出专家级结果。你可以把这些看作同一个趋势的不同切面，大模型的长程推理、工具使用和自主探索能力正在进入真实科研领域。密码学特别敏感，因为它和现实世界安全直接相连，所以一旦模型能力继续提升，实际后果会比纯数学开放问题更快到来。

Anthropic 的态度总体是谨慎乐观。他们说，这两个主要攻击都是预期中的结果。HAWK 处于 NIST 标准化评审阶段，本来就应该被找弱点。AES 七轮攻击则延续了几十年的 reduced round 研究路线，本来就不影响完整 AES。但他们也提醒，不应该假设模型能力会停在这里。仅仅一年时间，大模型就从无法分析最基础密码，到能发现多年人类专家评审没发现的设计弱点。世界上还有很多密码方案没有得到 AES 那样的充分审视，尤其是一些长尾系统、嵌入式设备、行业标准、私有协议，里面可能存在沉睡多年的弱点。AI 可以成为扩大审计覆盖面的机会，也可能让攻防节奏显著加快。

我个人的点评是，这篇文章真正重要的不是 HAWK 某个参数被削弱，也不是七轮 AES 加速二百到八百倍，而是它展示了一种未来安全研究的生产方式。大模型能读大量论文，能写实验，能提出数学结构，能和多个 worker 互相辩论，还能在几天内跑出人类需要很久才会系统尝试的路径。与此同时，它也会过早放弃，会自信地走错，会生成需要专家花数百小时验证的结果。所以未来最强的安全团队，可能不是单纯拥有最强模型的团队，而是最会把模型、工具、专家、披露流程和工程修复连接起来的团队。

最后收一下。Discovering cryptographic weaknesses with Claude 这篇文章告诉我们，Claude Mythos Preview 已经能在后量子签名候选 HAWK 和七轮 AES 这类严肃密码学问题上推动研究进展，但当前生产系统不需要因为这篇文章立刻变更。它真正带来的信号是，AI 正在进入密码学的对抗性评审流程，未来会帮助我们更早发现弱点，也会迫使人类重新设计验证和治理机制。对工程师来说，今天最该做的还是尊重标准、保持密码敏捷性、把 AI 当成强大的审计助手，而不是把它当成可以无条件信任的密码学权威。
