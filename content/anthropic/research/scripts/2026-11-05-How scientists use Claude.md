## Script

How scientists use Claude，中文可以译为，科学家如何使用 Claude。这篇文章发表于二〇二六年十一月五日，今天是二〇二六年十一月八日，距离发表只有三天。

欢迎收听 Claude FM。今天我们不聊模型又拿了什么竞赛成绩，而是聊一个更接近真实工作的问题。科学家每天打开 Claude，到底让它干什么？是提出惊人的新理论，还是清洗数据、改脚本、润色论文？这些看起来不那么耀眼的日常使用，究竟能让科学发现快多少？

这篇文章最值得听的地方，是它把三个经常混在一起的问题拆开了。模型理论上能做什么，研究人员实际上在用什么，以及用了之后，整个科研流程究竟能增加多少产出。这三件事有关联，却绝对不是同一件事。

先交代背景。文章提到，AlphaFold 已经预测了超过两亿个蛋白质的三维结构，材料领域也有系统预测大量潜在稳定晶体。数学研究中，人工智能正在参与猜想求解和证明验证。不过，这些亮眼案例不能直接回答一个普通实验室的问题：我们下个月的研究，究竟能因此快多少？

因为科研不是一道独立的考试题。它更像一条互相依赖的生产链，要选问题、读文献、设计实验、采集数据、分析结果，最后解释和沟通。某一步非常快，不代表整条链都快。文章真正想测量的，就是 AI 已经进入了这条链的哪些位置，以及哪些位置还卡着。

作者使用的主要样本，是二〇二六年八月二日至九月三十日之间，二十万七千零四十九次科研会话。其中大约十二万九千次来自聊天和知识工作界面，文章把它们统称为 Claude。另外大约七万八千次来自 Claude Code，也就是可以直接操作用户文件、编写和运行代码的编程工具。

这里有个重要边界。这些是消费者套餐上的会话，不是全球科学家的随机抽样，更不是所有科研人工智能产品的使用总账。我们能看到的是这几种产品中的科研活动切片，不能直接把比例推广成整个科学界的比例。

作者怎样判断一段对话是不是科研，又属于什么科研？他们让一个语言模型充当分类器，先识别科研会话，再按照固定分类体系，给会话标注领域、子领域和任务。这个体系叫 SciNet，可以理解成一份科学工作任务地图，覆盖三十四个领域、三百一十八个子领域，以及七千二百六十二项任务。

按照文章描述，研究团队保留和分析的是这些分类标签，而不是开放式提取研究内容。比如保留化学、数据清洗这样的类别，不提取和保存具体假说、未发表论文或者实验方法细节。报告也只展示汇总结果，而且需要满足最低数量的不同账户要求。

我个人认为，这种设计的意义，是让我们有机会观察科研工作结构，又尽量不碰研究本身的秘密。但也要理解代价。分类标签能告诉你大家在做什么类型的事，不能直接告诉你结论有没有做对，也不能证明某次对话真的产出了有价值的发现。

接下来先看谁在用。单看普通 Claude 会话，计算机科学占百分之十一点九，工程学占百分之八点四，医学占百分之七点七。这些领域本来研究人员就多，所以只看会话数量，还不足以判断哪个领域用得更积极。

作者于是换了一个分母，把会话占比和全球研究人员占比进行比较。就像比较不同城市的咖啡消费，不能只看卖出去多少杯，还得看有多少人口。人口很多的城市销量高，不一定意味着人均更爱喝。

这样一除，计算机、数学和统计学这些形式科学，使用强度就明显突出。社会科学在普通 Claude 上也比较活跃。相对来说，需要大量实验室操作的物理科学，以及涉及患者接触的医学，使用强度偏低。

到了 Claude Code，这种差异更大。计算机科学研究人员只占全球研究人员的百分之四点三，却贡献了百分之三十二点七的会话。进一步看子领域，人工智能与机器学习研究人员占比只有百分之一点二，却贡献了普通 Claude 百分之五的会话，以及 Claude Code 百分之十五点二的会话。

这里容易产生一个解释，说计算机研究人员更懂技术，所以当然先用。这可能是因素之一，但文章提供了更具体的线索：不管属于哪个大领域，带有计算性质的子领域通常都更积极，比如计算生物学、计算语言学和计算神经科学。

换句话说，决定工具是否顺手的，不只是你属于哪个院系，而是你每天的工作对象是什么。如果工作对象主要是文本、代码、数字文件，模型比较容易接进去。如果工作对象是一台需要调试的设备、一份等待培养的样本，或者一位需要面对面沟通的患者，光有聊天窗口就不够了。

那么，大家主要拿它做什么？文章把研究任务归为八类，包括数据分析、写作沟通、采集数据、阅读学习、理论分析、设计开发、构思假说，以及研究管理等其他工作。这里还排除了教学、同行评审等不直接生产新研究发现的任务。

最大的两块，是数据分析和写作。在普通 Claude 上，数据分析占百分之三十三点七，写作沟通占百分之三十二。在 Claude Code 上，数据分析接近一半，占百分之四十八点一。

但判断这些比例高不高，还需要另一个参照：研究人员原本在这些事情上花多少时间。文章使用任务体系中的时间估计，而不是给所有科学家安装计时器。这些估计由语言模型分类得到，并用记录任务时间的湿实验流程，以及大量论文中的任务频率进行验证。它是一个有校验的基准，但仍然不是精确的人类工时普查。

按照这个基准，研究人员大约百分之二十七点六的时间用于数据分析，百分之十六用于写作沟通。所以这两类任务在 Claude 会话里明显偏多。特别是写作，会话占比大约是时间占比的两倍。

相反，数据采集占研究人员时间的百分之二十八点六，却只占普通 Claude 会话的百分之十一点五。构思和假说生成占研究时间的百分之七点一，却只占普通 Claude 会话的百分之四点二，在 Claude Code 上更低。

注意，这些数字不代表 AI 已经节约了多少时间。一段分析对话可能持续很久，一段改写对话可能很短。会话占比衡量的是使用分布，不是工时替代率，更不是产出贡献率。这个区分很重要，否则很容易从大家常用，跳到它已经承担了同样比例的工作。

作者还调查了五百二十八位科学家，主要来自生命和健康科学，而且是积极使用 AI 的人。他们自报的使用情况，和会话分析大体一致：分析数据和写作最多，构思和采集数据较少。

有意思的是，当问他们哪些工作对重要研究成果最关键，排第一的是构思和假说生成，第二是采集数据。也就是说，当前使用最密集的地方，不一定是研究人员认为最决定科研价值的地方。

采集数据为什么少用，不难理解。模型能帮你设计记录表，不代表它能替你抽血、培养细胞或者走访受访者。但构思为什么也少用？作者给了几种可能：科学家更愿意自己想，觉得模型能力有限，或者构思本来就穿插在其他任务里，分类器没有单独识别出来。也可能模型确实还不擅长决定什么问题值得研究。

我个人认为，这一点对工程师特别有启发。你可能已经让模型把实现速度提高很多，但产品方向、实验目标、评价标准，仍然没有变清楚。把答案写得更快，和找到更值得回答的问题，是两种能力。前者改善了，不保证后者也跟着改善。

不过，文章没有把当前差距当成永远的天花板。它还观察了一个专门面向科学工作的工具，Claude Science。这个工具把原本分散的研究数据库和工具连接起来，试图把跨平台操作变成一个连续工作流。

文章举的场景是，一个生物学家想研究现有药物是否能作用于某个蛋白质。他可能得分别查询蛋白质功能、结构、已测试化合物，以及临床试验和论文。每个平台的数据结构、查询语言都不一样。研究者不只是思考科学，还在做大量信息搬运和格式翻译。

Claude Science 的思路，就是让模型能够在这些系统之间协调。这里的变化不只是聊天回答更专业，而是模型取得了完成任务所需的工具和上下文。就像一个再聪明的工程师，如果不能读仓库、不能运行测试，只能看别人粘贴的片段，工作能力也会被接口限制。

在生物和生物医学领域的比较中，提出蛋白质之间或蛋白质与小分子相互作用机制模型，这项任务出现在 Claude Science 的相对可能性，是普通 Claude 的五点六倍。这里说的是使用分布差异，不是质量提高五点六倍。

构思和假说生成在 Claude Science 上占到百分之八，大致接近这类任务占研究人员时间的比例，也大约是普通 Claude 对应占比的两倍。这提示我们，使用方式不完全由基础模型决定，工具连接和工作流设计，也可能改变用户愿意交给模型的问题。

文章还估计，Claude Science 会话对应的工作，如果没有 AI，所需人类工时接近其他界面的两倍；超过八成使用涉及博士训练水平的内容；超过七成会话具有较高自主性。但这些仍是分类和估计结果，不是经过独立验收的科研成功率。使用更复杂、更自主，不能自动等于研究更可靠。

接下来是全文最有技术味的一部分：作者怎么判断模型更擅长哪些任务？

他们没有逐项进行真实实验，而是建立了一个叫理论人工智能能力的指标。先把任务拆成更细的步骤，再让分类器两两比较：这两个步骤，AI 哪一个做得更好？比如解释统计检验和装填色谱柱，相比之下哪个更适合当前 AI。

大量比较之后，再用 Bradley Terry 模型汇总成评分。这个名字不必记住，你可以把它想象成比赛排名。选手不断两两交手，再根据胜负推断相对实力，思路类似棋类评级。最后，把一个任务里各步骤的评分平均，得到任务层面的能力分数。

这种方法有个方便之处，它不用假装所有任务都有统一的考试分数。但边界也很清楚：这是模型判断出来的相对适合程度，不是实测完成率，更不是安全部署的许可证。它能帮助解释宏观分布，却不能替你验收某个具体项目。

结果是，能力分数最低的五分之一任务，几乎看不到 Claude 使用。到了中间水平，使用占比和人类时间占比大体一致。而在能力最高的五分之一任务上，普通 Claude 的使用强度约为时间基准的两倍，Claude Code 约为四倍。

这意味着，至少从整体模式看，科学家不是随机把工作往模型里塞，而是倾向于把模型比较能做好的事情交给它。不过，这还是相关关系。能力分数和使用都可能受到数字化程度等共同因素影响，不能因此认定作者已经证明了唯一的因果链条。

那什么样的任务，模型更擅长？文章重点讨论强化学习，也就是让模型反复尝试，根据反馈改进的训练方式。适合这种学习的任务，通常有三个特点：结果容易验证，可以在计算环境里大量重复，反馈来得快。

想象你让模型修改一个函数，测试可以立刻告诉它通过还是失败。它能尝试不同实现，得到明确反馈。再想象你让模型判断一个新的社会理论，十年后能不能解释一种历史变化。你很难立刻给出准确奖励，也很难低成本重复一万次。

文章发现，能力评分与强化学习适合度的相关系数达到零点七八。认知性任务的能力评分通常更高，物理操作、人际互动，以及存在监管限制的任务通常更低。实际使用分布也表现出类似关系。

我个人认为，这里藏着一个很实用的产品判断。与其只问一个任务是不是足够聪明，不如问它能不能形成验证闭环。输入是否清楚，输出能否检查，错误能否定位，反馈是否及时。很多看起来普通的工程设计，恰恰决定了模型能否稳定工作。

但能力并不能解释所有差异。健康科学的使用量，相对任务能力评分仍然偏低，文章认为可能涉及医疗数据监管和集成困难。文本与代码占主导的领域，使用则可能高于能力评分所预测的水平。组织规则、数据接入和操作摩擦，会让能做与真正用上之间隔着一段距离。

说到这里，就可以回答最吸引人的问题了：科研到底能加速多少？作者给出了三个情景。先强调，这些是基于假设的推演，不是已经观察到的生产率提升，也不是未来时间表。

第一个情景，是当前能力得到广泛采用。第二个情景，是 AI 完全自动化百分之七十五的非物理研究步骤。第三个情景，是所有非物理步骤都被自动化。在这三个情景中，物理操作仍然由研究人员完成。

作者还区分了两个指标。一个叫 AI 承担份额，也就是现有研究工时里，有多少可能交给 AI。另一个叫加速倍数，指固定研究预算下，相比没有 AI，能够增加多少研究产出。这不是同一个数，也不意味着每一个项目的日历周期都按同样比例缩短。

模型把各种任务看作互相补充的投入。你不能靠写十倍的论文讨论，补上一次没有做的关键实验。与此同时，人也不是站着不动。当模型接过分析，人可以转去设计实验、提出问题或者处理其他瓶颈。所以它既不是简单相加，也不是永远被最慢的一步完全锁死。

成本假设也很重要。文章假定研究人员每小时成本九十五美元，AI 智能体每小时三十美元，而且每节约一小时人类工作，只需要运行零点二小时 AI。智能体可以理解成能连续执行一系列任务的人工智能系统。

按照这个假设，替代一小时人类工作对应的 AI 成本大约六美元，相比九十五美元，便宜到大约十六分之一。听到后面十五倍、十六倍这样的数字，要记住，这个成本设定就在背后支撑着上限，而不是模型凭空推导出了一个自然常数。

在当前能力广泛采用的情景中，AI 可能承担不同领域百分之二十七到百分之五十二的研究时间，中位数是百分之三十八。对应的研究产出，艺术领域大约是一点三五倍，化学约一点四一倍，计算机科学约一点九六倍，统计学约二点零二倍。

即使最适合 AI 的领域，也只是接近两倍。原因之一是当前大量工作仍然属于辅助或共同完成，人还要参与每个步骤。另一个原因是，任务之间互相依赖，而且 AI 本身也有成本。

这里的当前能力估计，还用到了那份积极采用者调查。作者把辅助、共同完成、委派和自主执行等使用层级，映射为不同的人类时间承担比例，再结合能力分数分配到具体步骤。这是一种建模选择，不是直接拿秒表测出来的节省，所以结果必须连着假设一起理解。

到了自动化四分之三非物理步骤的情景，计算机科学可以达到约八倍，统计学约七倍，经济学约六倍，而不少实验和医疗领域只有两到三倍。因为前者的数字任务更容易被选进自动化范围，后者还有大量必须亲自执行的步骤。

特别值得注意的是，非物理步骤的四分之三，不等于人类总工时的四分之三。不同步骤需要的时间不同，而且作者优先自动化能力分数较高的步骤。因此，不同领域被覆盖的实际工时比例会很不一样。

等到所有非物理步骤都自动化，图景又变了。统计、计算机、经济、数学，以及许多社会科学和人文学科，在模型里可以接近十五到十六倍。原来能力评分较低的认知任务，也不再构成限制。但生物、化学、材料等实验学科，仍然大约只有三到四倍。

原因是，这些领域约四成研究时间涉及物理步骤。你可以瞬间生成更多候选方案，但样品制备、仪器测量和实验过程仍然需要资源。厨房里多了十个会设计菜单的助手，不代表烤箱也凭空多出十台。

文章也承认，模型没有覆盖所有现实约束。大型设施的可用时段可能有限，设备和实验材料也很贵，而计算主要考虑研究人员与 AI 的时间成本。反过来，模拟如果能够替代部分物理实验，或者 AI 提出更好的假说，实际收益也可能更大。

所以我个人认为，这组数字最有用的不是拿来宣布某个领域即将增长十五倍，而是帮我们辨认瓶颈。你所在领域真正稀缺的，究竟是分析人手、设备、优质问题，还是获得可靠数据的能力？答案不同，投入方向就完全不同。

研究人员自己的预期也很积极。调查中，约四成受访者认为，到二〇三〇年，AI 可以独立完成完整科研项目；到二〇三五年，这个比例约为百分之六十四。不过，也有百分之十六认为永远不会发生。对于自主产生科学突破，预期更谨慎。

这些是积极使用 AI 的生命和健康科学研究人员的判断，不是全体科学家的共识，更不是达成时间承诺。完整项目和重大突破也不是一回事。完成一个定义明确的研究流程，不代表自动选出了最重要的问题。

那对每天写代码、做模型、搭平台的听众，今天可以怎么用？下面这些是我根据文章提出的实践建议，不是作者做过的对照实验。

我会先把一个具体项目拆成步骤，而不是笼统地说，我们要引入 AI。比如一次模型效果研究，拆成问题定义、数据获取、数据检查、实验实现、统计分析、结果解释和报告。分别写清楚，哪里消耗人时，哪里必须等待外部资源，哪里允许工具直接操作。

接着选数字化程度高、反馈明确的环节开始。比如让模型检查数据模式、生成可视化脚本、搭建基准实验，或者比较两种分析实现。但不要只要求它给一个看起来合理的结论，要同时要求可复现的过程、明确的输入来源，以及可以运行的验证办法。

举个假想例子，你要比较两个推荐模型。如果直接问哪一个更好，模型很容易围绕总体指标编一套顺耳的解释。更好的流程，是先固定数据切分和指标定义，再让它实现计算，由你检查样本覆盖、分组差异和异常情况。模型可以加快计算，但不能替你默默决定什么叫更好。

然后，把验证成本算进去。模型十分钟写完分析，人花两个小时排查错误，不一定比自己做更划算。你可以记录任务总时长、返工次数、结果能否复现，以及最终是否通过验收。不要把回答生成速度，当成团队生产率。

对于知识密集型工作，可以借鉴 Claude Science 的启发，优先解决数据与工具的连接问题。如果研究人员每天都要手动下载、改格式、找字段，那么换一个更强模型，未必比打通可靠接口更有效。但连接更多系统，也意味着权限更大，要限制访问范围，保留执行记录，避免把便利变成不可追踪的操作。

构思环节则可以采用不同的合作方式。我个人建议，不急着让模型宣布最佳研究方向，而是让它列出互相竞争的解释，指出每种解释需要什么证据，以及哪项实验最能区分它们。这样，它是在扩大你的比较空间，而不是用流畅语言代替研究判断。

如果你负责团队管理，还可以问一个不那么炫酷的问题：我们是否应该先自动化那些没人喜欢的行政负担？文章引用的美国调查显示，联邦资助项目负责人报告，约百分之四十四的研究时间用于行政要求。这个比例不能直接套到中国团队，但它提醒我们，科研加速不一定从最前沿的推理任务开始，也可能从减少重复填报和协调开始。

最后还有安全和激励。论文更容易生产，不代表知识就更容易验证。如果产出数量暴涨，同行吸收和审查的能力可能跟不上。组织如果仍然只奖励数量，AI 可能放大的首先是数量，而不是质量。

自主性越高，也越需要在人类关键决策处保留检查。尤其在生物等具有双重用途风险的领域，什么问题可以研究、可以采用什么方法、哪些结果可以传播，不应只由系统一路执行。文章明确指出，有些安全检查值得我们接受更慢的进展。

这篇文章留给我们的核心判断是，AI 科研的现实入口仍然是数据分析和写作，而能否进一步加速，取决于能力、工具、成本与物理瓶颈能不能一起改善。我个人认为，真正重要的不是让科学家产出更多文字，而是让他们用更可靠的流程，验证更多值得研究的问题。这里是 Claude FM，我们下期再见。
